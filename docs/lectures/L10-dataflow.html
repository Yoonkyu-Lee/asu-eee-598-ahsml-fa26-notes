계산은 하나도 안 바꾸고 순서만 바꾼다. 그런데 그 순서가 어느 데이터가 PE 안에 붙어 있고 어느 데이터가 메모리에서 계속 끌려오는지를 정하고, 그게 곧 에너지다. 이 강의는 그 순서에 dataflow라는 이름을 붙이고, output stationary와 weight stationary를 PE 하나부터 3D conv, NVDLA까지 따라간다.

Not one operation changes, only the order. Yet that order decides which data stays pinned inside a PE and which keeps getting dragged in from memory, and that is the energy bill. This lecture names the order a dataflow and follows output stationary and weight stationary from a single PE through 3D convolution to NVDLA.

L06의 일곱 글자 N, K, C, P, Q, R, S와 H, W가 그대로 나온다. 새 기호는 둘이다. spatial_for(병렬로 펼친 loop, 13쪽)와 c_t·c_s 같은 타일 첨자(바깥 시간 loop와 안쪽 공간 loop로 쪼갠 같은 차원, 31쪽). 제일 중요한 식은 12쪽의 MAC = RSCPQK이고, 각 텐서의 "크기 × 재사용"이 전부 이 값과 같다는 것이 5번 절의 요지다.

Lecture 6's seven letters N, K, C, P, Q, R, S plus H, W return unchanged. Two new pieces of notation: spatial_for (a loop unrolled in parallel, page 13) and tile subscripts like c_t and c_s (one dimension split into an outer time loop and an inner space loop, page 31). The key equation is page 12's MACs = RSCPQK; section 5's point is that each tensor's "size × reuse" equals exactly that.

이 강의는 어느 층이고 어느 지표를 움직이나. L01 42쪽 지도에서 하드웨어 층과 소프트웨어(mapping) 층의 경계에 있다. dataflow는 하드웨어가 지원하는 순서(배선과 레지스터 위치로 박힌다)이면서, 컴파일러가 고르는 순서(loop를 어떻게 쌓고 쪼갤지)이기 때문이다. 움직이는 지표는 Efficiency(에너지)가 첫째다. 정확도는 한 비트도 안 바뀐다. 덧셈 순서만 바뀌므로 부동소수점 반올림 차이를 빼면 결과가 같다.
Which layer is this, and which metric does it move. On lecture 1's page-42 map it sits on the border between the hardware layer and the software (mapping) layer: a dataflow is an order the hardware supports (baked into wiring and register placement) and an order the compiler chooses (how loops are stacked and split). The metric it moves is efficiency (energy) first. Accuracy does not change by a single bit; only the order of additions changes, so apart from floating-point rounding the results are identical.

Titled Convolution loop nest. The figure on the left and the code on the right are the same slide as lecture 6's page 18. It opens this lecture for one reason: this lecture is about reordering exactly these loops.

그림은 파란 입력 H×W×C 덩어리 N개, 초록 filter R×S×C K개, 빨간 출력 P×Q×K N개다. 코드에는 괄호 두 개가 붙어 있다. 바깥 네 loop(n, k, p, q)에 for each output activation, 안쪽 세 loop(r, s, c)에 convolution window. 출력 원소 하나를 고르고, 그 창 안을 다 돌며 누적한 뒤, Activation()을 건다.

The figure shows N blue inputs of H×W×C, K green filters of R×S×C, and N red outputs of P×Q×K. The code carries two braces: the outer four loops (n, k, p, q) are labelled for each output activation, the inner three (r, s, c) convolution window. Pick one output element, sweep its window accumulating, then apply Activation().

L06 5번 절의 표가 이 강의 전체의 열쇠다. 일곱 겹 loop nest에서 정리했듯, weight는 n, p, q와 무관하고, 입력은 k와 무관하고, 출력은 r, s, c와 무관하다. 어떤 텐서와 무관한 loop를 가장 안쪽에 두면, 그 loop가 도는 동안 그 텐서는 가만히 있다. 이 문장이 "stationary"의 정의 전부다. 슬라이드 2쪽의 순서는 r, s, c가 안쪽이므로 출력이 가만히 있는 순서, 즉 OS다.
The table in lecture 6 section 5 is the key to this whole lecture. As the seven-deep loop nest laid out, weights ignore n, p, q, inputs ignore k, and outputs ignore r, s, c. Put the loops a tensor ignores innermost, and that tensor holds still while they spin. That sentence is the whole definition of "stationary." Page 2's order has r, s, c innermost, so the output holds still: it is OS.

The same 200 as lecture 7-8-9's page 56, "one DRAM access = 200 MACs." That page measured instruction energy with Horowitz-style 45nm numbers; this one is Eyeriss measuring in 65nm. Different processes, same order of magnitude, and that is the point. What is new is the middle rungs. A buffer at 6x means "on-chip is cheap" is only half true: a few hundred kB of SRAM costs six times the RF. So a dataflow aims to cut buffer accesses too, not only DRAM ones.

읽기 셋, 쓰기 하나. 여기서 눈여겨볼 것은 partial sum(부분합)이 읽기와 쓰기에 두 번 나온다는 것이다. 누적 중인 값은 MAC 한 번마다 꺼냈다가 다시 넣어야 한다. 나중에 OS가 왜 강한지(부분합을 PE 안에 붙잡아 두면 이 두 화살표가 통째로 사라진다)의 복선이다.

Three reads, one write. Note that the partial sum appears twice, once as a read and once as a write. A value under accumulation has to come out and go back in on every MAC. This foreshadows why OS is strong: pin the partial sum inside the PE and both arrows vanish.

"접근 넷"은 최악의 경우이자 단순화다

"Four accesses" is a worst case and a simplification

5쪽 계산은 MAC마다 psum을 읽고 쓴다고 가정한다. 실제로 첫 번째 MAC은 psum을 읽을 필요가 없고(0에서 시작), 마지막 MAC 뒤에만 써도 된다. 그래도 슬라이드가 4를 쓰는 건 "아무 재사용도 안 할 때의 상한"을 보여주려는 것이다. 이 숫자를 실제 AlexNet 칩의 DRAM 접근으로 인용하면 안 된다. 실제 칩은 이보다 두세 자리수 적게 접근하려고 만든다.

Page 5's arithmetic assumes the psum is read and written on every MAC. In reality the first MAC needs no psum read (it starts from zero) and you only need to write after the last. The slide still uses 4 to show the ceiling with zero reuse. Don't quote it as a real AlexNet chip's DRAM traffic: real chips are built to touch DRAM two or three orders of magnitude less.

함정Trap

dataflow ≠ dataflow architecture

Dataflow is not a dataflow architecture

컴퓨터 구조 교과서에서 "dataflow"를 찾으면 프로그램 카운터 없이, 피연산자가 다 도착한 명령부터 실행하는 기계(Dennis의 dataflow machine 등)가 나온다. 비순차 실행 CPU의 Tomasulo 알고리즘도 "제한된 dataflow"라고 부른다(보충). 이 수업의 dataflow는 그 뜻이 아니다. 구별 기준은 순서를 누가 정하느냐다. dataflow architecture에서는 데이터 도착이 실행 순서를 정한다(동적). DNN 가속기의 dataflow에서는 설계자가 loop nest로 미리 고정한다(정적). DNN은 데이터 의존성이 실행 전에 다 알려져 있어서 정적으로 정할 수 있다. 그게 이 분야가 가능한 이유다.

Look up "dataflow" in an architecture textbook and you get machines with no program counter that execute whichever instruction has all its operands (Dennis's dataflow machine and others); Tomasulo's algorithm in out-of-order CPUs is called "restricted dataflow" too (supplementary). This course's dataflow is not that. The test is who fixes the order. In a dataflow architecture, data arrival decides the order (dynamic). In a DNN accelerator's dataflow, the designer fixes it in advance with a loop nest (static). DNN data dependencies are fully known before execution, so the order can be static, and that is what makes this whole field possible.

1D Convolution Example: OS와 WS는 loop 두 줄의 순서1D convolution example: OS and WS are the order of two loop lines

위에 파란 입력 a b c d e(길이 W), × 청록 weight 1 2 3(길이 S), = 빨간 출력 A B C(길이 Q). 5 − 3 + 1 = 3이다. 아래에 코드 두 개.

At the top: blue input a b c d e (length W) × teal weights 1 2 3 (length S) = red output A B C (length Q), since 5 − 3 + 1 = 3. Two pieces of code below.

// Output Stationary (OS)
for (q=0; q<Q; q++) {
  for (s=0; s<S; s++) {
    OA[q] += IA[q+s] * W[s];
  }
}
// Weight Stationary (WS)
for (s=0; s<S; s++) {
  for (q=0; q<Q; q++) {
    OA[q] += IA[q+s] * W[s];
  }
}

안쪽 loop와 무관한 텐서가 "stationary"다. OS 코드의 안쪽은 s인데 OA[q]에는 s가 없다. 그래서 안쪽 loop가 도는 S번 동안 OA[q]는 같은 자리다. WS 코드의 안쪽은 q인데 W[s]에는 q가 없다. Q번 동안 같은 weight다. 입력 IA[q+s]는 두 인덱스에 다 걸려 있어서 어느 쪽에서도 가만히 있지 않는다. 1D에서 IS가 등장하지 않는 이유는 아래 감각 문제에서 본다.

The tensor that ignores the inner loop is the "stationary" one. OS's inner loop is s, and OA[q] has no s, so for the S inner iterations OA[q] stays at the same address. WS's inner loop is q, and W[s] has no q: the same weight for Q iterations. The input IA[q+s] depends on both indices, so it never sits still in either. The exercise below shows why IS doesn't appear in 1D.

OS와 WS는 원래 코드의 두 loop(q, s)를 바꿔 쌓기만 하면 됐다. 입력은 q+s라는 합으로 인덱싱되므로, 입력을 붙잡으려면 loop 변수 자체를 바꿔야 한다(q 대신 w = q + s). 그 대가로 경계 검사(if)가 생기고, 가장자리 입력은 S번보다 적게 쓰인다. 12쪽의 "~RSK"에 물결표가 붙은 이유가 이 if다. 안쪽 S번 동안 IA[w]는 가만히 있고, weight는 매번 바뀌며, psum은 매번 다른 OA[q]를 읽고 쓴다.

OS and WS just restacked the original two loops (q, s). The input is indexed by a sum, q+s, so pinning it requires changing the loop variable itself (w = q + s instead of q). The price is a bounds check (if), and edge inputs get used fewer than S times. That if is why page 12 writes "~RSK" with a tilde. For the S inner iterations IA[w] holds still, the weight changes every time, and the psum reads and writes a different OA[q] each time.

With C = 3, only 3 of the 16 c_s rows are used, while K = 64 fills all 64 columns: 3 × 64 = 192 / 1,024 = 18.75%. The other 81% of PEs sit idle, so a layer with plenty of MACs runs at a fifth of peak on this array. With K = 1000 there are ⌈1000/64⌉ = 16 tiles, the last using only 1000 − 15·64 = 40 columns, for a column utilisation of 1000 / (16·64) ≈ 97.7%. The moment hardware fixes a spatial_for bound, layers that don't fit it lose utilisation. That is where lecture 7-8-9's "nobody hits peak" comes from, and one reason Eyeriss chose a dataflow that spreads dimensions other than C, K (supplementary).

함정Trap

"stationary"는 "영원히 안 움직인다"가 아니다

"Stationary" does not mean "never moves"

WS 칩도 weight를 바꾼다. 29쪽 코드에서 curr_w는 안쪽 p, q loop 동안만 고정이고, 바깥 r, s, c, k가 한 칸 돌 때마다 새로 읽힌다. "stationary"는 가장 안쪽 loop들이 도는 동안 RF에 머문다는 상대적인 말이다. 그래서 같은 WS라도 안쪽 loop가 얼마나 긴지(PQ가 크면 오래 머문다)에 따라 이득이 달라진다. FC 층(PQ = 1)에서 WS는 weight를 한 번 쓰고 바로 바꾼다. 이름만 WS다.

A WS chip changes weights too. In page 29's code, curr_w is fixed only during the inner p, q loops and is re-read whenever the outer r, s, c, k advance. "Stationary" is relative: it means staying in the RF while the innermost loops run. So the payoff of the same WS depends on how long the inner loops are; a big PQ keeps the weight longer. On an FC layer (PQ = 1), WS uses each weight once and swaps it straight away: WS in name only.

In page 33's OS array (8 PEs), how many values are read from the global buffer each cycle? And in page 35's WS array? (Steady state, with weights already loaded.)

답Answer

OS: 9개. 입력 8개(PE마다 다른 값) + weight 1개(broadcast). psum은 PE 안이라 0. WS: 입력 8개 + psum 읽기 1(PE 0 쪽) + psum 쓰기 1(PE 7 쪽) = 10개. weight는 0. 거의 같아 보이지만 한 사이클에 일어나는 MAC은 둘 다 8번이다. 차이는 WS가 8개짜리 합 하나를 만들고 OS가 8개의 서로 다른 합에 한 항씩 더한다는 데 있다. 그 결과 psum이 버퍼를 오가는 횟수는 WS 쪽이 MAC 8번당 2번, OS는 출력이 끝날 때 8개를 한 번에 쓴다. 9번 절 도구가 PE 하나로 셌던 것과 다른 결론이 나오는 이유가 이웃 전달이다.

OS: 9. Eight inputs (different per PE) plus one weight (broadcast); the psums stay inside, so 0. WS: 8 inputs + 1 psum read (at PE 0) + 1 psum write (at PE 7) = 10, and 0 weights. Nearly equal, but both perform 8 MACs per cycle. The difference is that WS builds one sum of eight terms while OS adds one term to eight different sums. So WS moves the psum through the buffer twice per 8 MACs, while OS writes its 8 finished outputs once at the end. Neighbour forwarding is why this differs from the single-PE count in section 9's tool.
