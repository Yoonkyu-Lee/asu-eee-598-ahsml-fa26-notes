L10이 dataflow를 loop 순서로 적었다면, 이 강의는 그 loop를 실제로 돌리는 회로를 짓는다. 곱셈기 하나에서 출발해 넓히고(vectorization), 쪼개고(pipelining), 섞고(interleaving), 그다음 SRAM이 그 곱셈기들을 굶기지 않게 포트와 bank를 붙인다. 끝에서 그 조각들이 TPU의 weight stationary systolic array와 output stationary systolic array로 모인다.

Lecture 10 wrote dataflow down as loop order; this lecture builds the circuit that actually runs those loops. It starts from one multiplier, widens it (vectorization), slices it (pipelining), interleaves it, and then gives the SRAM enough ports and banks that the multipliers never starve. At the end the pieces come together as the TPU's weight-stationary systolic array and an output-stationary systolic array.

Lecture 10 boiled down to these two snippets: the same 1D conv, with only the order of two loop lines swapped.

// OS: output stays
for (q = 0; q < Q; q++)    // output position
  for (s = 0; s < S; s++)  // filter tap
    OA[q] += IA[q+s] * W[s];
// WS: weight stays
for (s = 0; s < S; s++)    // filter tap
  for (q = 0; q < Q; q++)  // output position

L10 12번 절의 결론은 이랬다. 어떤 텐서와 무관한 loop를 가장 안쪽에 두면 그 텐서가 PE 안에 붙어 있다(stationary). for는 시간으로 돌고, spatial_for는 PE 여러 개로 펼친다. OS는 psum을 붙잡고 weight를 broadcast하고, WS와 IS는 weight나 입력을 붙잡고 psum을 이웃 PE로 넘긴다. 그리고 NVDLA는 spatial_for c, k를 16 × 64로 자른 WS였다.

Lecture 10 section 12 landed here: put the loops a tensor ignores innermost and that tensor stays pinned in the PE (stationary). A for runs in time; a spatial_for is spread across many PEs. OS pins the psum and broadcasts weights; WS and IS pin a weight or an input and pass psums to neighbouring PEs. And NVDLA was WS with spatial_for c, k cut to 16 × 64.

그런데 L10은 PE를 ⊗⊕가 그려진 상자로만 그렸다. 상자 안이 어떻게 생겼는지, 한 사이클에 몇 번 곱하는지, 버퍼가 그 상자에 무엇을 몇 바이트씩 대 주는지는 말하지 않았다. 이 강의가 그 빈칸을 채운다. 아래 표가 L10의 말과 이 강의의 회로를 한 줄씩 짝지은 것이다.

곱셈기는 싸고 빠르다. 어려운 건 그 곱셈기를 매 사이클 바쁘게 두는 것이다. 시간 쪽으로는 pipelining과 interleaving으로 매 사이클 새 일을 시작하게 하고(II = 1), 데이터 쪽으로는 SRAM의 포트, bank, 전용 버퍼, double buffering으로 피연산자를 제때 대 준다. 그리고 포트를 무작정 늘리는 대신 한 번 읽은 값을 여러 곱셈기가 나눠 쓰게(spatial reuse) 배치한 것이 systolic array다.

Multipliers are cheap and fast. The hard part is keeping them busy every cycle. On the time side, pipelining and interleaving let a new operation start each cycle (II = 1); on the data side, SRAM ports, banks, dedicated buffers and double buffering deliver operands on time. And the systolic array is the layout that, instead of piling on ports, lets many multipliers share each value read once (spatial reuse).

Which layer is this, and which metric does it move. On lecture 1's page-42 map it is the hardware layer, specifically what page 2 calls microarchitecture (arithmetic-unit design and memory organisation). The wording is a little slippery, so read it off the figure. Simple dual-port is page 37's diagram exactly: two ports, one write-only and one read-only (1R1W), so one write and one read per cycle. True dual-port lets each of the two ports either read or write (2RW), so a cycle can do two reads. When you need to feed a multiplier two operands, that's a big difference: simple gives one read per cycle, true gives two.

함정Trap

"dual-port"는 "읽기 둘"이 아니다

"Dual-port" does not mean "two reads"

벤더 문서나 FPGA 블록 RAM 설정 창에서 "dual-port RAM"을 보면 보통 simple dual-port(읽기 하나 + 쓰기 하나)다. 이름에 "dual"이 있다고 한 사이클에 두 번 읽힌다고 기대하면 설계가 틀린다. 판단 기준은 "읽기 포트가 몇 개인가" 하나다. 곱셈기를 바쁘게 두는 것은 읽기 포트이고, 쓰기 포트는 다음 데이터를 채우는 쪽이다.

When a vendor datasheet or an FPGA block-RAM wizard says "dual-port RAM," it usually means simple dual-port (one read + one write). Expect two reads per cycle because the name says "dual" and the design breaks. The one test is "how many read ports?" Read ports keep multipliers busy; the write port is for refilling.

ASIC에서 왜 비싼가 (보충). SRAM 셀 하나는 6T 래치에 포트마다 접근 트랜지스터와 wordline, bitline이 붙는다. 읽기 포트를 하나 더 달면 모든 셀에 트랜지스터 몇 개와 선 몇 가닥이 더 붙는다(대략 6T → 8T). 셀이 커지면 배열이 커지고, 선이 길어지면 접근마다 충전할 정전용량이 커져 에너지와 지연이 함께 는다. 포트 8개짜리 SRAM은 같은 용량의 단일 포트 SRAM보다 몇 배 크다.

Why it's expensive in an ASIC (supplementary). Each SRAM cell is a 6T latch plus, per port, access transistors, a wordline and bitlines. Add one read port and every cell gains a few transistors and wires (roughly 6T → 8T). Bigger cells make a bigger array, and longer wires mean more capacitance to charge per access, so energy and delay rise together. An eight-port SRAM is several times larger than a single-port SRAM of the same capacity.

FPGA에서 왜 복제인가. FPGA의 block RAM은 포트 수가 공장에서 정해져 있다(보통 2). 읽기가 더 필요하면 같은 내용을 담은 BRAM을 여러 개 두고, 쓰기는 모든 사본에 똑같이 하고, 읽기는 사본마다 하나씩 한다. 용량이 복제 수만큼 낭비된다. 그리고 쓰기 포트가 여럿이면 두 쓰기가 같은 주소에 동시에 오는 경우를 정해야 한다(누가 이기나, 막을 건가). 그래서 청록 NOTE가 붙었다.

Why duplication on an FPGA. FPGA block RAMs have a port count fixed at the factory (usually 2). Need more reads? Keep several BRAMs with identical contents, write every copy the same way, and read one per copy. Capacity is wasted by the copy count. And with several write ports you must decide what happens when two writes hit the same address in the same cycle (who wins, or do you block?), hence the teal NOTE.

ECE 479 Lec17-18의 #pragma HLS ARRAY_PARTITION이 FPGA 쪽 답이다. 배열 하나를 여러 BRAM으로 쪼개(complete, cyclic, block) 한 사이클에 여러 원소를 읽게 했던 것. 복제(45쪽)가 아니라 나누기라서 용량을 낭비하지 않지만, 대신 동시에 읽는 원소들이 서로 다른 조각에 있어야 한다. 그게 47쪽의 bank다.
ECE 479 lecture 17-18's #pragma HLS ARRAY_PARTITION is the FPGA answer. It split one array across several BRAMs (complete, cyclic, block) so one cycle could read several elements. It's splitting, not duplicating as on page 45, so no capacity is wasted, but the elements read together must sit in different pieces. That's page 47's banks.

Read it as applying the cache-hierarchy principle to the port problem. A large, many-ported SRAM is expensive (page 45), so give the large SRAM few ports and put many small registers right beside the multipliers; small registers are cheap even with ports. Fetch frequently used values once from the big SRAM, keep them in small registers and use them many times, and the multipliers see what looks like a large, fast, many-ported memory. The rest of this deck (from page 48) implements this rule: systolic registers, dedicated buffers, double buffering.

L07-8-9 19번 절의 메모리 계층과 같은 말이다. 거기서는 "데이터를 연산 가까이(LOCALITY), 가까이 온 데이터로 할 수 있는 연산을 전부(REUSE)"였다. 그때는 에너지(DRAM 200×)가 이유였고, 여기서는 포트 수(대역폭)가 이유다. 같은 처방이 두 병을 같이 고친다.
The same idea as lecture 7-8-9 section 19's memory hierarchy: "bring data close to compute (LOCALITY), then do everything you can with it (REUSE)." There the reason was energy (DRAM at 200x); here it's port count (bandwidth). One prescription cures both.

What "app-specific" means. A CPU cache doesn't know what data will come, so it mixes everything in one cache. An accelerator knows there are only three tensors, so it sizes and ports each separately. TPUv1 gives activations 24 MiB and 167 GiB/s, and weights only a FIFO and 30 GiB/s. Weights are pinned in the array (WS) and used for a long time, so little bandwidth suffices; activations enter fresh every cycle and need a wide road. That judgement is baked straight into the numbers.

This PE is weight stationary. The multiplier keeps multiplying activations by W_0's weight while the next tile's weight loads into W_1; when the current tile ends, only the mux flips. L06과 L10의 conv loop에서 K는 filter(출력 채널) 수, N은 batch였다. 54쪽 행렬곱에서 K는 축소 차원(conv라면 C·R·S), N은 출력 열 수(conv라면 filter 수)다. 즉 conv의 K가 행렬곱의 N 자리로 간다. 논문을 읽을 때 어느 관례의 K인지부터 확인한다. GEMM 문헌(BLAS)은 54쪽 관례를 쓴다.

In lectures 6 and 10's conv loops, K was the filter (output-channel) count and N the batch. The last multiply is at k = 2: cycle = i + j + k = 1 + 2 + 2 = 5, product a1,2*b2,2, matching page 70 (cycle 5) where PE (1,2) completes its three terms. SRAM reads: 3 on the left edge (one a per row) + 3 on the top edge (one b per column) = at most 6. Up to 7 PEs work in a cycle (page 68), so without reuse it would need 14. For an N×N array, 2N edge values feed N2 MACs; the reuse ratio grows as N/2, 64x for a 128×128 MXU.
