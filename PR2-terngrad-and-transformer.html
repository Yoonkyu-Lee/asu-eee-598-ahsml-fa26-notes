ㅎㅇ. Paper Reading #2 두 편 오늘 한 번에 조진다. 스압 개쩌니까 3줄요약부터 박고 간다.

3줄요약
  1. TernGrad: 분산학습에서 worker들이 gradient를 주고받는 게 병목임. 그래서 gradient를 {−1, 0, +1} × 숫자 하나로 뭉개서 보냄. 대충 뭉개는 게 아니라 확률적으로 뭉개서 평균은 원래 값이랑 똑같게 만들고, 그래도 학습이 수렴한다는 걸 수식으로 증명함.
  2. Transformer: 번역 모델에서 RNN이 한 글자씩 순서대로 돌아야 해서 느림. 그래서 RNN을 통째로 버리고 attention(행렬곱 덩어리)만으로 모델을 만듦. 병렬로 쫙 돌아가니까 학습이 훨씬 싸지고 BLEU도 당시 최고 찍음.
  3. 둘 다 결국 "하드웨어가 잘하는 모양으로 문제를 바꿔라"라는 얘기임. 하나는 네트워크로 옮기는 바이트를 줄이고, 하나는 GPU가 병렬로 할 수 있는 일을 늘림.

핑프용 읽는 순서

둘이 분야가 좀 다름. TernGrad는 시스템 + 최적화 이론 논문이고, Transformer는 모델 아키텍처 논문임. 그래서 막히는 데가 다름.

서지

초록을 핑프어로

분산학습은 gradient 동기화 통신 비용이 병목인 게 국룰임. 우리는 gradient를 세 값 {−1, 0, 1}로만 표현하는 TernGrad를 제안함. gradient 크기에 bound가 있다는 가정 아래 수렴을 수학적으로 증명했고, 그 bound를 보고 layer-wise ternarizing이랑 gradient clipping을 만들어서 수렴을 개선함. AlexNet은 정확도 손실 없음(오히려 오름), GoogLeNet은 평균 2% 미만 손실. 마지막으로 성능 모델로 확장성까지 봄.

논문이 스스로 밝힌 기여는 네 개임 (1절 끝).

  1. gradient에 ternary(3값)를 써서 통신 줄임
  2. gradient에 대한 통계적 bound를 제시해서 TernGrad의 수렴을 일반적으로 증명함
  3. layer-wise ternarizing과 gradient clipping으로 그 bound를 표준 SGD bound에 가깝게 당김
  4. 압축 gradient 학습의 속도를 평가하는 성능 모델을 만듦

통신이 왜 빌런인가

논문 1절 + 3.1절. 이거 모르면 뒤에 전부 이해 안 됨. 천천히 감.

상황 설정: 모델 하나를 GPU 여러 장으로 학습함

모델이 크고 데이터가 많으면 GPU 한 장으로 학습하면 몇 주 걸림. 그래서 여러 장에 나눠서 돌림. 나누는 방법 중 제일 흔한 게 data parallelism임.

용어 뜯어보기 · data parallelism
풀네임data parallelism, 데이터 병렬화
한 줄모든 worker가 모델 전체 사본을 들고, 데이터만 나눠서 각자 gradient를 계산함
언제모델이 GPU 한 장에 들어갈 때. 2017년엔 거의 이거였음
누가PyTorch DDP, Horovod, TensorFlow 분산 전략의 기본값
헷갈리는 것model parallelism은 반대로 모델을 쪼개서 여러 장에 나눠 담는 것. AlexNet이 GPU 2장에 층을 반씩 나눈 게 그쪽에 가까움

한 iteration이 어떻게 도는지 보자. 논문 Figure 1이 이거임.

  1. mini-batch를 N등분해서 worker i한테 zt(i)를 줌
  2. worker마다 자기 몫으로 gradient gt(i) 계산
  3. 전부 parameter server로 보냄 (push)
  4. server가 평균 냄
  5. 평균 낸 걸로 parameter 갱신하고 그걸 다시 worker들한테 뿌림 (pull)

3번이 gradient synchronization, 5번이 parameter synchronization임. 둘 다 네트워크로 모델 크기만큼의 데이터가 오가는 일임.

근데 worker를 늘리면 왜 안 빨라짐?

논문 1절 요지: worker 늘리면 계산 시간은 확 줄어듦. 근데 통신 시간은 안 줄거나 오히려 늚. 결국 어느 순간부터 통신 시간이 계산 절약분을 다 까먹음 (논문 표현으로 "amortize the savings of computation time").

왜냐면 worker 한 명이 보내는 양은 worker 수랑 상관없이 모델 크기 그대로거든. 계산은 N으로 나눠지는데 통신은 안 나눠짐. 이게 핵심임.

기존 탈출구: asynchronous SGD

흔한 해결책이 asynchronous SGD임. 동기화 끝날 때까지 안 기다리고 옛날 값(stale value)으로 그냥 계속 계산함. 논문이 꼽는 문제 둘:

  • worker마다 parameter가 달라져서 정확도가 떨어지고 가끔 발산함 (참고문헌 [15], [16])
  • 작업 타이밍에 따라 결과가 달라져서 학습이 비결정적이고 디버깅이 헬임

그래서 이 논문은 synchronous SGD는 유지하고, 대신 보내는 데이터 자체를 줄이는 쪽으로 감. 스코프도 논문이 밝혀놨음: Asynchronous SGD랑도 합칠 수 있지만 이 논문은 Figure 1의 동기식 분산 SGD만 다룸.

함정

synchronous vs asynchronous를 "빠름 vs 느림"으로 외우지 마셈

구별 기준은 "다음 iteration을 시작하기 전에 모두의 gradient가 합쳐지길 기다리냐" 하나임. sync는 기다려서 느리지만 결과가 단일 GPU SGD랑 수학적으로 같음. async는 안 기다려서 빠르지만 stale gradient로 갱신하니까 다른 알고리즘이 됨. TernGrad는 sync의 결정성을 지키면서 통신을 줄이는 쪽임.

강의 연결. Lecture 4-5의 memory-bound vs compute-bound랑 똑같은 구도임. 거기선 칩 안에서 "DRAM에서 가져오는 속도 vs 연산 속도"였고, 여기선 칩 밖에서 "네트워크로 보내는 속도 vs GPU 연산 속도"임. 층만 바뀌었지 "데이터 옮기는 게 연산보다 비싸다"는 결론은 같음.

선행연구 족보

2절 Related work. 이거 알아야 "그래서 이 논문이 뭐가 새로운데?"에 답할 수 있음.

통신 줄이는 방법은 크게 두 갈래임.

  • Sparsification: 작은 gradient는 아예 안 보냄. 큰 것만 보냄
  • Quantization: 전부 보내되 비트 수를 줄여서 보냄

TernGrad는 quantization 쪽이고, 논문은 둘이 orthogonal(서로 독립이라 같이 쓸 수 있음)하다고 말함.

QSGD랑은 뭐가 다름? (리뷰 쓸 때 제일 중요한 문단)

논문이 직접 "concept은 같다"고 인정함. 둘 다 stochastic rounding으로 unbiased 양자화하는 거라서. 대신 세 가지가 앞선다고 주장함:

  1. 수렴을 gradient의 통계적 bound 관점에서 증명함. 그리고 이 bound가 QSGD에서 왜 여러 개의 quantization bucket이 필요한지도 설명해줌
  2. 이 bound를 보고 layer-wise ternarizing과 gradient clipping을 설계함. 즉 이론이 실제 기법을 이끌어냄
  3. 3단계만 써서 AlexNet top-1 정확도가 0.92% 올랐음. QSGD는 4단계로 1.73% 떨어졌고, 손실을 없애려면 4 bit(16단계) 이상이 필요했음

  1. 벡터 전체에서 제일 큰 절댓값 s를 찾음
  2. |gk| / s 확률로 동전 앞면. 이 비율은 항상 0~1 사이임 (s가 최댓값이니까)
  3. 앞면이면 gk를 부호는 그대로 두고 크기를 s로 뻥튀기함. 뒷면이면 0으로 만듦

그러면 보낼 건 원소마다 {−1, 0, +1} 중 하나 + float 하나(s)뿐임.

왜 "그냥 반올림" 안 하고 동전을 던짐?

이게 제일 중요한 포인트임. deterministic rounding(그냥 가까운 쪽으로 반올림)을 하면 0.3s짜리는 매번 0이 됨. 작은 gradient는 영원히 0이 되는 거임. 그럼 그 방향으로는 학습이 영원히 안 됨.

동전을 던지면 10번 중 3번은 +s로 가니까 평균적으로는 0.3s만큼 움직임. 수식으로:

E[s · sign(gk) · bk] = s · sign(gk) · |gk| / s = gk

이걸 unbiased(편향 없음)라고 함. 논문은 이 stochastic rounding이 QSGD도 똑같이 택한 방식이고 저정밀 연산에서 이미 검증된 기법이라고 밝힘 ([20], [30]).

무대 설정: online learning

논문은 수렴을 online learning 시스템 틀에서 분석함. 관측 z가 모르는 분포에서 하나씩 뽑혀 나오고, loss Q(z, w)로 성능을 잼. 줄이고 싶은 건 loss의 기댓값:

C(w) ≜ E{Q(z, w)}식 (5)

기준이 되는 알고리즘은 Bottou의 GOGA(General Online Gradient Algorithm, [33])임. 그냥 SGD라고 보면 됨:

wt+1 = wt − γtgt = wt − γt · ∇wQ(zt, wt)식 (6)

TernGrad는 여기서 gt 자리에 ternary를 넣은 것:

wt+1 = wt − γt(st · sign(gt) ∘ bt)식 (8)

그리고 04에서 본 대로 기댓값이 원래 gradient랑 같음 (식 10):

E{st · sign(gt) ∘ bt} = E{gt} = ∇wC(wt)

핵심: 왜 가정 3이 원래 가정보다 "세냐"

원래 GOGA의 gradient bound는 이거임:

E{‖g‖²} ≤ A + B‖w − w*‖²식 (18), 표준 SGD

그리고 항상 이게 성립함:

‖g‖∞ · ‖g‖1 ≥ ‖g‖²식 (19)

왜냐면 ‖g‖² = Σgk² = Σ|gk|·|gk| ≤ Σ max|g| · |gk| = ‖g‖∞‖g‖1. 곱하는 한쪽을 최댓값으로 바꿨으니 커질 수밖에 없음.

그래서 TernGrad의 가정 3은 왼쪽이 더 큰 값인데 같은 상한 아래 있어야 하니까 더 까다로운(stronger) 가정임. 좌변이 커질수록 만족하기 어려움.

(보충) 이 좌변이 사실 ternary gradient의 "크기 제곱의 기댓값"임. 원소 하나를 보면 g̃k²은 확률 |gk|/s로 s², 아니면 0임. 그래서 E[g̃k²] = s|gk|이고, 다 더하면 E‖g̃‖² = s · Σ|gk| = ‖g‖∞‖g‖1. 즉 가정 3은 "ternary gradient에 대해 원래 SGD랑 똑같은 bound를 건 것"이라고 읽으면 한 방에 이해됨. 원래 값보다 커진 만큼(=‖g‖∞‖g‖1 − ‖g‖²)이 ternarize가 추가한 분산임.

논문의 곁다리 결과도 하나 있음: 같은 절차로 gradient에 Gaussian noise N(0, σ²)를 더한 GOGA도 E{‖g‖²} ≤ A + B‖w − w*‖² − σ² 아래서 수렴함을 증명할 수 있다고 함 (식 20). bound는 더 세지지만, gradient noise가 파라미터 공간 탐색을 도와 정확도를 올린다는 선행 관찰([34])이 있고, TernGrad의 랜덤성도 비슷하게 탐색을 도와 일부 모델에서 정확도를 올린다고 연결함.

기술 1 · layer-wise ternarizing

gradient 범위는 backprop 하면서 layer마다 다름. 그러니 전체에 scaler 하나 쓰지 말고 layer마다 따로 s를 구해서 ternarize함. 심지어 같은 layer 안에서도 weight랑 bias를 따로 함.

더 잘게 쪼개서 bucket마다 따로 하면(QSGD 방식) 표준 bound에 더 가까워지지만 float scaler가 늘어서 통신이 늚. bucket 크기가 1이면 그냥 float gradient가 돼버림. 즉 bucket 크기는 정확도와 통신 사이의 다이얼임. 03에서 "bound가 QSGD의 bucket 필요성을 설명한다"는 게 이 얘기였음.

실험 2: ImageNet

4.2절. 본게임. AlexNet이랑 GoogLeNet.

그냥 바꿔 끼우면 안 됐다: 수정 세 가지

논문이 솔직하게 적음: 큰 DNN에서 float을 ternary로 그냥 바꾸고 나머지 하이퍼파라미터 그대로 두면 정확도 손실이 좀 생길 수 있음. 그래서 아래 중 일부나 전부를 적용함:

  1. dropout 비율 낮추기 (더 많은 뉴런 유지). 이유: dropout도 랜덤성으로 규제하고 TernGrad도 랜덤성을 넣으니까, 둘 다 세면 "과한 랜덤"이 됨
  2. weight decay 줄이기. 같은 이유. TernGrad 랜덤성이 이미 규제 역할을 함
  3. 마지막 분류 layer는 ternarize 안 함. 레이블 one-hot 때문에 마지막 layer gradient 분포가 한쪽으로 쏠리는데(skew), 대칭인 {−1, 0, 1}은 이런 분포에 안 맞음. 비대칭 ternary도 방법이지만 단순하게 그냥 float로 보냄. 비용은 작음: 마지막 layer는 전체 parameter의 AlexNet 6.7%, ResNet-152 3.99%

그 외 세팅: 전부 momentum SGD, conv layer에 Batch Normalization. AlexNet은 Caffe 하이퍼파라미터와 augmentation, GoogLeNet은 polynomial LR decay와 [41]의 augmentation. GoogLeNet 구현은 auxiliary classifier 없음. 검증 정확도는 가운데 crop만으로 평가.

RNN의 태생적 한계: 한 줄로 서서 기다림

RNN(LSTM, GRU 포함)은 hidden state ht를 이전 hidden state ht−1와 t번째 입력의 함수로 만듦. 즉 h5를 계산하려면 h4가 있어야 하고, 그건 h3이 있어야 하고... 50단어 문장이면 50번을 순서대로 해야 함.

논문이 짚는 문제:

  • 이 순차성 때문에 한 학습 예제 안에서 병렬화가 안 됨
  • 문장이 길수록 치명적임. 메모리 제약 때문에 여러 예제를 batch로 묶는 것도 한계가 있어서
  • factorization trick([18])이나 conditional computation([26]) 같은 개선이 있었지만 순차 계산이라는 근본 제약은 그대로
하드웨어 관점 번역 (보충). GPU는 수천 개 연산기를 동시에 돌려야 제값을 함. RNN은 한 스텝에서 하는 일이 "d차원 벡터 × d×d 행렬" 하나뿐이라 연산기 대부분이 놀고, 다음 스텝은 이번 스텝 끝나야 시작함. 연산기를 채울 방법이 batch를 키우는 것뿐인데 그건 메모리가 막음. 알고리즘의 데이터 의존성이 하드웨어 활용률의 상한을 정하는 전형적인 예임. Lecture 4-5의 DNN 계산 관점에서 본 "데이터 의존성" 얘기가 바로 이거.

attention은 원래 RNN의 보조였음

attention 자체는 새로운 게 아님. 입력이나 출력 안에서 거리에 상관없이 의존성을 모델링할 수 있어서 이미 필수 부품이었음([2] Bahdanau, [16]). 근데 거의 항상 RNN이랑 같이 씀. 이 논문의 한 수는 "보조였던 attention을 본체로 올리고 RNN을 빼버리자"임. 그래서 제목이 "Attention Is All You Need".

Encoder (N = 6층)

똑같은 층 6개를 쌓음. 층마다 sub-layer 둘:

  1. multi-head self-attention
  2. position-wise fully connected feed-forward network

attention의 정의

논문 정의: attention은 query 하나와 key-value 쌍 여러 개를 출력 하나로 매핑하는 함수. 전부 벡터임. 출력은 value들의 가중합이고, 각 value의 가중치는 query와 그 value에 대응하는 key의 궁합(compatibility)으로 정함.

핑프용 비유: 도서관 검색

Query = 내가 검색창에 친 검색어. Key = 책마다 붙은 태그. Value = 책 내용. 검색어랑 태그가 잘 맞을수록 그 책 내용을 많이 가져옴. 결과물은 "관련도 비율대로 책 내용을 섞은 것"임. 다만 진짜 검색이랑 다른 건, 딱 한 권만 고르는 게 아니라 전부 조금씩 섞는다는 것. 그래서 미분이 되고 학습이 됨.

왜 √dk로 나눔? (시험 단골)

흔한 attention 함수는 둘임:

  • additive attention([2]): 궁합을 hidden layer 하나짜리 feed-forward network로 계산
  • dot-product (multiplicative) attention: 이 논문 거랑 똑같은데 1/√dk 스케일만 없음

이론상 복잡도는 비슷한데 dot-product가 실제로는 훨씬 빠르고 메모리도 덜 먹음. 고도로 최적화된 행렬곱 코드로 구현할 수 있어서.

문제는: dk가 작을 땐 둘이 비슷한데, dk가 크면 스케일 없는 dot-product가 additive보다 못함([3]). 저자들의 추측(“We suspect”): dk가 크면 내적 값이 커져서 softmax가 gradient가 극도로 작은 영역으로 밀려남. 그래서 1/√dk로 줄임.

각주 4의 설명: q, k의 원소가 평균 0, 분산 1인 독립 확률변수라면 q·k = Σi=1dk qiki는 평균 0, 분산 dk. 분산 1짜리 곱 dk개를 더했으니까. 표준편차는 √dk임. 그러니까 √dk로 나누면 분산이 다시 1로 돌아옴.

7절 결론과 향후 과제

  • Transformer = encoder-decoder의 recurrent layer를 multi-head self-attention으로 바꾼 최초의 attention 전용 transduction 모델
  • 번역에서 recurrent, conv 기반보다 훨씬 빨리 학습되고 두 과제 모두 새 SOTA. 영→독은 기존 모든 앙상블도 이김
  • 향후: 텍스트 말고 이미지, 오디오, 비디오 같은 다른 입출력으로 확장. 큰 입출력을 효율적으로 다루는 local, restricted attention 연구. 그리고 생성을 덜 순차적으로 만들기
마지막 향후 과제에 주목. Transformer가 병렬화한 건 학습임. 학습 땐 정답 문장을 통째로 넣고 mask로 가리면 되니까 모든 위치를 동시에 계산함. 근데 실제로 번역을 생성할 때(inference)는 여전히 auto-regressive라서 한 토큰씩 순서대로 만들어야 함. 논문이 이걸 스스로 남은 숙제로 적어둠. Lecture 4-5의 training vs inference 구분이 여기서 그대로 살아남.

TernGrad 3줄요약
  1. 분산학습에서 worker가 매번 보내는 FP32 gradient가 병목. 그래서 원소마다 {−1, 0, +1} + layer마다 float scaler 하나로 보냄 (2 bit 기준 16배 감소)
  2. 그냥 반올림이 아니라 |g|/s 확률로 동전 던지기라서 평균이 원래 gradient와 같음(unbiased). gradient bound 가정 하나만 바꿔서 SGD 수렴 증명을 그대로 가져옴
  3. 이론이 "최댓값 s가 크면 불리"라고 알려줘서 layer-wise scaler + 2.5σ clipping을 만듦. AlexNet 정확도 유지(batch 1024에선 +0.92%), GoogLeNet 평균 2% 미만 손실, 속도는 성능 모델로 AlexNet 8 GPU 3.04× 추정
Transformer 3줄요약
  1. RNN은 순서대로 돌아서 병렬화가 안 됨. 그래서 RNN 버리고 attention만: softmax(QKT/√dk)V. √dk는 내적 분산이 dk라서 softmax 포화 막으려고 나눔
  2. multi-head(8개) + FFN + residual/LayerNorm을 6층씩 쌓은 encoder-decoder. 순서 정보는 sin/cos positional encoding으로 더해줌. decoder는 mask로 미래를 못 봄
  3. self-attention은 순차 연산 O(1), 경로 O(1), 대신 계산 O(n²d). 번역 문장처럼 n < d면 이득. 결과는 영→독 28.4, 영→불 41.0(단일 모델 최고), base 모델 학습 비용 3.3·1018 FLOPs
