Software 2.0 and hardware

다섯 장이 한 이야기다. 계산이 더 많아지자 머신러닝이 이겼고, 그 계산은 CPU가 아니라 GPU에서 왔다. L01에서 이미 들은 이야기인데, 이번에는 "왜 CPU가 아닌가"에 한 줄이 더 붙는다.

Five slides, one story: more compute let machine learning win, and that compute came from GPUs, not CPUs. You heard it in lecture 1; this time one more line is attached to "why not the CPU".

Jeff Dean의 두 곡선Jeff Dean's two curves

제목 Machine Learning Today. 그래프 하나다. 가로축은 Data size, model complexity, 세로축은 Accuracy. 곡선이 둘이다. 주황색 Conventional algorithms는 처음에 빠르게 오르다가 금방 평평해진다. 초록색 Machine Learning은 처음엔 주황색 아래에 있다가 꾸준히 올라서 교차하고, 끝까지 오른다.

함정Trap

"Bad for control flow"는 이 수업 후반부의 복선이다

"Bad for control flow" is foreshadowing

두 슬라이드의 세 줄 설명은 대칭이다. CPU는 control flow에 강하고, GPU는 약하다. 이걸 "GPU가 CPU의 상위 호환"으로 읽으면 안 된다. 교환이다. GPU는 분기를 포기하고 병렬성을 샀다.

The two slides' three-line captions mirror each other: the CPU is strong at control flow, the GPU weak. Do not read this as the GPU strictly dominating the CPU. It is a trade: the GPU gave up branching to buy parallelism.

이 반례가 무슨 말인지 풀어 보자. 인버터 몇 개를 고리로 이으면 ring oscillator가 된다. 스스로 계속 0과 1을 뒤집는 회로다. 인버터가 한 번 뒤집는 것을 "연산 한 번"이라고 세면, 수 GHz로 뒤집으면서 전력은 마이크로와트 단위다. TOPS/W가 어마어마하게 나온다. 그런데 이 회로는 아무것도 계산하지 않는다. 입력도 없고 쓸모 있는 출력도 없다.

Unpack the counterexample. Chain a few inverters into a loop and you get a ring oscillator, a circuit that flips between 0 and 1 on its own. Count each flip as one "operation", and it flips at gigahertz rates while drawing microwatts. Its TOPS/W is enormous. And it computes nothing: no input, no useful output.

이 반례가 드러내는 구멍은 셋이다. (1) "operation"의 정의가 없다. 1비트 뒤집기와 FP32 곱셈이 같은 1로 세어진다. (2) 데이터 이동이 빠져 있다. 인버터는 메모리를 안 읽는다. 실제 칩의 에너지 대부분이 어디로 가는지(39쪽, 54쪽)를 이 지표는 못 본다. (3) peak 기준이다. 실제 워크로드에서 그 속도가 나오는지를 안 묻는다.

The counterexample exposes three holes. (1) "Operation" is undefined: a one-bit flip and an FP32 multiply both count as 1. (2) Data movement is left out: an inverter reads no memory, and the metric cannot see where most of a real chip's energy goes (pages 39 and 54). (3) It is a peak figure, and it never asks whether a real workload reaches that speed.

"total"과 "peak" activation은 다른 숫자다

"Total" and "peak" activations are different numbers

상자에 total/peak #activations라고 슬래시로 붙어 있지만 둘은 다른 질문에 답한다. total은 모든 층의 activation을 다 더한 것이고 DRAM 트래픽을 결정한다. peak는 추론 중 한 순간에 동시에 살아 있어야 하는 최대량이고 on-chip 메모리 용량을 결정한다. 층 하나가 끝나면 그 입력은 버려도 되기 때문에 peak가 total보다 훨씬 작다. MCU처럼 SRAM이 수백 kB인 기계에서는 peak가 모델을 올릴 수 있느냐를 가른다.

The box joins them with a slash, total/peak #activations, but they answer different questions. Total sums every layer's activations and sets DRAM traffic. On a microcontroller with a few hundred kB of SRAM, peak decides whether the model runs at all.

Titled What is OPs/byte of a DNN?

  • Operational intensity [OPs/Byte]는 DNN의 연산 대 메모리 접근 비율을 수치화한다

  • Operational intensity [OPs/byte] quantifies the ratio of computation to memory access of a DNN
  • Total operations = multiplications + additions
  • operational intensity = total number of operations / bytes accessed
  • For simplicity we assume, e.g., a big-enough on-chip memory: bytes accessed = size of parameters + size of activations. An upper bound on operational intensity. Pen and paper calculation!

"상한"이라는 말이 중요하다. on-chip이 충분히 크다는 가정은 모든 가중치와 activation을 DRAM에서 딱 한 번씩만 읽는다는 뜻이다. 실제로는 on-chip이 모자라서 같은 데이터를 여러 번 다시 읽는다. 그러면 분모가 커지고 intensity가 내려간다. 펜과 종이로 구한 값은 가장 운 좋은 경우의 x좌표이고, 실제 점은 그보다 왼쪽에 있다. 이 차이를 줄이는 게 60~62쪽의 reuse와 다음 강의들의 dataflow다.

"Upper bound" is the key phrase. A big-enough on-chip memory means every weight and activation is read from DRAM exactly once. In reality on-chip memory runs short and data gets re-read, the denominator grows, and intensity drops. The pen-and-paper value is the luckiest possible x coordinate; the real point sits to its left. Closing that gap is what reuse on pages 60 to 62, and the dataflow lectures after this, are about.

왜 같은 MLP0가 x좌표 세 개를 갖는가

Why does one MLP0 have three x coordinates?

이 슬라이드에서 가장 이상한 점이 이거다. intensity는 워크로드의 성질이라면서, 같은 워크로드가 칩마다 다른 x에 찍혀 있다. 답은 17쪽에 있다. batch가 다르다. 원 논문에 따르면 이 서비스들에는 응답 시간 상한(MLP0는 7 ms)이 있었고, 그 안에 들어오도록 각 칩에서 batch를 골랐다. TPU는 빨라서 batch를 크게(200) 잡을 수 있었고, CPU와 GPU는 7 ms 안에 들려면 batch를 작게(16) 잡아야 했다(보충, Jouppi et al. 2017의 표). FC 층에서 intensity ≈ batch였으니(8번 절 감각 문제) 점이 그만큼 왼쪽으로 간다.

This is the slide's strangest feature. Intensity is supposedly a property of the workload, yet one workload lands at a different x on each chip. The answer is on page 17: the batch sizes differ. Per the original paper, these services carried a response-time ceiling (7 ms for MLP0), and each chip's batch was chosen to fit under it. The TPU was fast enough to use a large batch (200); the CPU and GPU had to keep the batch small (16) to stay within 7 ms (supplement, from a table in Jouppi et al. 2017). Since intensity ≈ batch for an FC layer (section 8's exercise), the points move left accordingly.

이게 latency와 throughput의 교환이 roofline 위에서 보이는 방식이다. latency 상한이 batch를 묶고, batch가 intensity를 묶고, intensity가 성능을 묶는다. 38쪽의 마지막 줄 "Low latency has an additional constraint of small batch size"가 이 그림 한 장의 요약이다.

This is how the latency-throughput trade shows up on a roofline. The latency ceiling caps the batch, the batch caps intensity, and intensity caps performance. The last line of page 38, "low latency has an additional constraint of small batch size", summarises this whole chart.

이 그림이 이 덱에서 가장 대학원다운 한 장이다. 커널은 하나고 성능(y)도 하나인데 x가 넷이다. 각 층의 AI는 "그 층을 통과한 바이트"로 나눈 것이기 때문이다. L1은 모든 접근을 보니 바이트가 가장 많고 AI가 가장 작다. SysMem은 캐시를 다 빠져나온 것만 보니 바이트가 가장 적고 AI가 가장 크다.

This is the most graduate-level slide in the deck. One kernel, one performance (y), four x values, because each level's AI divides by the bytes that crossed that level. L1 sees every access, so it has the most bytes and the smallest AI. SysMem sees only what escaped every cache, so it has the fewest bytes and the largest AI.

  • 두 점 사이의 가로 거리가 그 층의 reuse다. HBM 점과 SysMem 점이 멀리 떨어져 있으면, HBM에서 가져온 데이터를 여러 번 써서 SysMem까지 안 내려갔다는 뜻이다. 그게 High Reuse 화살표다
  • 어느 층이 병목인가는 "어느 점이 자기 사선에 가장 가까운가"로 판정한다. 자기 사선에 딱 붙은 점이 있다면 그 층의 대역폭이 지금 성능을 묶고 있다
  • The horizontal gap between two points is that level's reuse. If the HBM and SysMem points are far apart, data fetched from HBM was used many times and never had to come from SysMem. That is the high reuse arrow
  • Which level is the bottleneck is decided by which point sits closest to its own diagonal. A point right on its diagonal means that level's bandwidth is what is capping performance now

슬라이드 제목이 "Energy and Power"로 둘을 묶었지만 제약의 모양이 다르다. energy(J)는 일 한 번의 총비용이고 배터리 수명을 정한다. power(W = J/s)는 순간 소비율이고 열을 정한다. 마지막 글머리가 power 이야기다. 칩에 MAC을 아무리 많이 깔아도 동시에 다 켜면 타 버린다. L01의 dark silicon 이야기다. 그래서 power 상한은 throughput 상한으로 바뀐다.

The title bundles "energy and power", but the constraints are shaped differently. Energy (J) is the total cost of one job and sets battery life. Power (W = J/s) is the instantaneous rate and sets heat. The last bullet is about power: however many MACs you lay down, switch them all on at once and the chip cooks, lecture 1's dark silicon. So a power ceiling turns into a throughput ceiling.

구별 기준은 "시간으로 나눴는가"다. 한 작업을 느리게 돌리면 power는 줄지만 energy는 거의 안 준다(오히려 누설 전류 때문에 늘 수도 있다). TOPS/W는 OPs/s ÷ J/s = OPs/J라서 사실 energy 효율 지표다.

The test is whether time was divided out. Running a job slower lowers power but barely touches energy (leakage can even raise it). TOPS/W is OPs/s ÷ J/s = OPs/J, so it is actually an energy-efficiency metric.

평가 순서 다섯 단계The evaluation process, five steps

DNN 시스템이 어떤 응용에 쓸 만한지를 평가하는 순서는 이럴 수 있다.

The evaluation of whether a DNN system is viable for a given application might go:

  1. Accuracy가 그 태스크를 할 수 있는지를 정한다
  2. Latency와 throughput이 충분히 빠르고 실시간으로 돌 수 있는지를 정한다
  3. Energy와 power가 처리를 할 수 있는 기기의 form factor를 주로 정한다
  4. Cost(주로 칩 면적과 외부 인터페이스가 정한다)가 이 솔루션에 얼마를 낼지를 정한다
  5. Flexibility가 지원 가능한 태스크 범위를 정한다
  1. Accuracy determines whether it can perform the task
  2. Latency and throughput determine whether it runs fast enough and in real time
  3. Energy and power primarily dictate the form factor of the device it can run in
  4. Cost, dictated mainly by chip area and external interfaces, determines what one would pay
  5. Flexibility determines the range of tasks it can support

순서가 필터다. 1번에서 떨어지면 2번을 볼 필요가 없다. 3번의 "form factor"는 구체적이다. 수 와트면 스마트폰, 수십 와트면 노트북, 수백 와트면 서버 랙이다. 전력이 기기의 종류를 정한다.

The order is a filter: fail step 1 and step 2 does not matter. Step 3's "form factor" is concrete: a few watts is a phone, tens a laptop, hundreds a server rack. Power decides what kind of device it can be.

왜 가중치를 50배 줄였는데 에너지가 늘었나

Why did 50x fewer weights cost more energy?

원그래프가 답이다. SqueezeNet의 에너지에서 가중치는 21%뿐이다. 가중치를 50배 줄여도 전체 에너지의 5분의 1만 건드린 것이다. 나머지 70%가 activation(입력 23% + 출력 47%)이다. SqueezeNet은 가중치를 줄이려고 1×1 conv로 채널을 쥐어짰다가 다시 펴는 fire module을 반복하는데, 그 과정에서 층이 늘고 중간 feature map이 늘었다. 가중치 대신 activation을 더 많이 옮기게 된 것이다.

The pie is the answer. In SqueezeNet's energy, weights are only 21%. Cutting weights 50x touches a fifth of the total. The other 70% is activations, 23% input plus 47% output. SqueezeNet shrinks weights with repeated fire modules that squeeze channels with 1×1 convolutions and expand them again, which adds layers and intermediate feature maps. It traded moving weights for moving more activations.

그리고 computation은 10%다. 90%가 데이터 이동이다. 이 원그래프 하나가 39쪽의 "데이터 이동이 에너지를 지배한다"의 실측 증거다. 아래 Movidius 그래프도 같은 이야기를 GFLOPS/W로 한다. TX1에서 SqueezeNet은 AlexNet의 약 1/4 효율이다. 정확도는 둘 다 83%로 같다.

And computation is 10%: 90% is data movement. This one pie is the measured evidence for page 39's "data movement dominates energy." The Movidius chart says the same in GFLOPS/W: on a TX1, SqueezeNet runs at about a quarter of AlexNet's efficiency, at the same 83% accuracy.

Model size and memory traffic are different numbers

"모델이 작다"는 보통 가중치 파일의 크기를 말한다. 저장 공간과 다운로드 크기에는 정확한 지표다. 하지만 추론 한 번에 움직이는 바이트는 가중치 + activation이고, 작은 모델일수록 activation 쪽 비중이 커진다. 구별 기준은 "디스크를 재는가, 버스를 재는가"다. 12쪽 상자의 "model size"와 "total/peak #activations"가 따로 적혀 있는 이유다.

"A small model" usually means a small weight file, an accurate measure of storage and download size. But the bytes moved per inference are weights plus activations, and the smaller the model, the larger the activation share. The test is whether you are measuring the disk or the bus. That is why page 12's box lists "model size" and "total/peak #activations" separately.

Why multiplies shrink far more than adds is the heart of the table. 슬라이드가 층마다 이름을 다섯 개씩 적은 건 분야마다 부르는 이름이 달라서다. CPU 쪽은 cache, 가속기 논문은 on-chip buffer / global buffer, GPU(CUDA)는 shared memory. 그런데 CUDA 용어 하나가 이 그림과 정반대로 간다. CUDA의 "local memory"는 스레드 전용이지만 실제로는 칩 밖 DRAM에 있다. 레지스터가 넘칠 때(spill) 쓰는 곳이라 느리다. 이 슬라이드의 "Local Memory"(PE 안, KB)와 이름만 같다. 구별 기준은 "누가 쓰나"가 아니라 "물리적으로 어디 있나"다. 그리고 CUDA의 "global memory"는 슬라이드대로 DRAM이 맞다.

The slide gives each level five names because each community names it differently: CPU people say cache, accelerator papers say on-chip or global buffer, GPU (CUDA) people say shared memory. 함정Trap

순서 2가 공짜로 이기는 게 아니다

Ordering 2 does not win for free

슬라이드는 가중치 저장만 보여준다(각주). 출력 줄을 보면 이야기가 뒤집힌다. 순서 1의 출력은 0,0,0,0,1,1,1,1,… 이라 부분합 하나를 네 번 연달아 누적하고 끝낸다(출력 reuse distance 1). 순서 2의 출력은 0,1,2,3,0,1,2,3,… 이라 부분합 네 개를 동시에 들고 있어야 한다(출력 reuse distance 4). 가중치 버퍼를 줄인 만큼 부분합 버퍼가 늘었다.

The slide shows weight storage only (see the footnote). Look at the output rows and the story flips. Ordering 1's outputs run 0,0,0,0,1,1,1,1,…, so one partial sum is accumulated four times in a row and finished (output reuse distance 1). Ordering 2's outputs run 0,1,2,3,0,1,2,3,…, so four partial sums must be held at once (output reuse distance 4). What the weight buffer saved, the partial-sum buffer spent.

어느 데이터의 reuse distance를 1로 만들지 고르는 것이 dataflow다. 순서 2처럼 가중치를 PE에 붙여 두면 weight stationary, 순서 1처럼 부분합을 붙여 두면 output stationary. 다음 강의들의 이름이 이 그림 한 장에서 나온다. L04-5의 "가중치를 instruction처럼 심어 둘 것인가"가 이 선택의 다른 이름이다.

Choosing which data gets reuse distance 1 is what a dataflow is. Pin the weights in the PE as in ordering 2 and you have weight stationary; pin the partial sums as in ordering 1 and you have output stationary. The names of the coming lectures come out of this one picture, and lecture 4-5's "plant the weights like instructions?" is another name for the same choice.

The red question at right, why a smaller reuse distance with spatial reuse?, and two answers: fewer memory read ports → less area; fewer reads → less power.

세 격자를 비교하면 답이 보인다. 순서 1은 한 사이클에 값 하나만 읽어서 네 곳에 뿌린다. 읽기 포트 하나, 읽기 한 번. 순서 3은 매 사이클 네 소비자가 서로 다른 값 넷을 원한다. 포트가 넷 필요하거나, 한 번 읽은 0을 t3까지 어딘가에 들고 있어야 한다. spatial reuse는 "여러 PE가 동시에 같은 값을 원하게" 순서를 짜는 것이고, 그러면 reuse distance가 0에 가깝게 줄어 버퍼도 포트도 줄어든다. systolic array가 데이터를 이웃 PE로 흘려보내는 방식이 이 발상의 하드웨어판이다. 다음 강의들에서 본다.

Compare the three grids and the answer appears. Ordering 1 reads one value per cycle and fans it to four places: one read port, one read. Ordering 3 has the four consumers wanting four different values every cycle: four ports, or holding the 0 somewhere until t3. Spatial reuse means ordering things so many PEs want the same value at the same time, which shrinks reuse distance toward zero and with it the buffers and ports. A systolic array passing data to its neighbouring PEs is the hardware version of this idea, coming up in the next lectures.

감각 문제Get a feel

Run page 61's 1D convolution (7 inputs, 4 weights, 4 outputs) on four PEs. If you order it so all four PEs use the same weight each cycle, what does each PE receive? How many cycles, and how many weight reads?

답Answer

PE k가 출력 k를 맡는다. 사이클 t에 가중치 wt를 네 PE에 한 번에 뿌리고, PE k는 입력 xk+t와 곱해 자기 부분합에 더한다. 4사이클, 가중치 읽기 4번(가중치마다 1번). 16번 곱셈을 하는데 가중치는 4번만 읽었으니 가중치 하나당 spatial reuse 4다(출력 4개에 한 번에). 부분합은 각 PE 안에 머문다(temporal reuse). 이게 62쪽 순서 1이고, 가중치는 공간으로 재사용, 부분합은 시간으로 재사용하는 조합이다.

PE k owns output k. At cycle t, weight wt is broadcast to all four PEs, and PE k multiplies it by input xk+t into its own partial sum. 4 cycles, 4 weight reads, one per weight. Sixteen multiplies on four reads is spatial reuse of 4 per weight, while each partial sum stays inside its PE (temporal reuse). That is page 62's ordering 1: weights reused across space, partial sums across time.
