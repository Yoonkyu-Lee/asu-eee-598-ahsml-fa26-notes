# CP33 — 서브별 집합 맞추기: 박스는 가입한 서브만 받는다 (H12)

- 상태: 완료 (층 1 무작위 진행 중, 2026-11-17)
- 목적형. **[디자인] [구현] [측정]**
- 질문: 두 박스가 **함께 가진 서브만** 맞추도록 바꾸면 (1) 박스가 가입 안 한 서브를 하나도 안 받고 (S5), (2) CP29–CP30의 성질(S1–S4, L1, L2, F1, 전달)을 그대로 지키며, (3) 비용 관문을 넘는가? 넘으면 칩 일은 "내 서브에 온 유효 메시지 수 × (검증 1 + 인코딩 1)"로 고정된다.
- 왜 (CP32): 한 화면 데모 3단계에서 서브 B 글이 서브 B 밖 박스로 갔다. 집합 맞추기(CP29~)가 서브를 안 가리고, 받는 쪽도 안 거른다. 동기화 모델에 서브가 없어서 층 1–3이 못 봤다.
- NORTHSTAR와의 연결: 7-6 "이웃 대신 모두"의 사례. 하드웨어 숫자(칩 일)를 말하기 전에 프로토콜이 쓸데없는 일을 안 시키게 한다. 4번 불변식은 안 건드린다.

## 그림

```
 지금 (CP29–CP32, "leak")                         고친 것 ("sub")
 ┌ box X: 서브 {A, B} ┐   ┌ box Y: 서브 {A} ┐        ┌ box X {A, B} ┐   ┌ box Y {A} ┐
 │ keys: A 글, B 글   │⇄⇄│ keys: 전부       │        │ keys[A] keys[B]│⇄│ keys[A]    │   맞추는 범위 = {A,B} ∩ {A} = {A}
 └────────────────────┘   └──────────────────┘        └────────────────┘   └────────────┘
   맞추기: 전부 비교 → Y가 B 글을 받음 (검증·저장)      맞추기: A만. 지문은 id 합이라 서브별 지문을 더하면 됨
   받기: 서브 안 봄                                    받기: 내 서브가 아니면 검증 전에 거절 (rej_sub)
   push: 서브 보유자에게만 (원래 맞음)                 push: 그대로

 이웃 고르기 (sub에서 새로 필요한 것)
   B 글은 이제 B 회원끼리만 흐른다 (비회원이 중계 안 함) → 각 박스는 자기 서브마다 켜진 이웃 회원이 D_SUB = 3명 이상 있게
   이웃을 채운다 (모자라면 그 서브 회원 중에서 hello). 이웃을 줄일 때(D_HI) 서브의 마지막 회원 이웃은 안 뺀다.
   탐색 hello(E)와 후보는 서브가 하나라도 겹치는 박스 중에서.
```

## 대안

| | 무엇을 맞추나 | 고르면 / 바꿀 조건 |
|---|---|---|
| T1 | 서브마다 세션 따로 | 공통 서브 수만큼 세션·지문. T2의 결과가 같고 비용이 더 크면 버림 |
| **T2** | **한 세션, 공통 서브의 합집합** (지문 = 서브별 지문의 합 mod 2⁶⁴, 키 목록 = 병합) | **고름**. 세션 수·와이어 형식 그대로 |
| T3 | 맞추기는 전부, 받는 쪽만 거름 | 매 세션 남의 서브 id가 차이로 다시 나옴 (비용 ∝ 남의 서브 크기, 영원히). 버림 |
| T4 | P-all을 설계로 인정 | 칩·저장 숫자를 1.06·1.28배로 (CP16 출처). **sub가 아래 관문에서 떨어지면** 이쪽 |

| | 이웃 | |
|---|---|---|
| **M1** | **한 메시 + 서브마다 회원 이웃 D_SUB 보장** | 고름 |
| M2 | 한 메시 그대로 (서브 무시) | 작은 서브의 회원끼리 이웃이 아닐 수 있음 → 전달 실패 예상 |
| M3 | 서브마다 메시 따로 (gossipsub 토픽 메시) | 이웃·바닥 비용 ∝ 서브 수. M1이 작은 서브에서 빠짐을 내면 |

**가정 (표시)**: 서브의 회원 박스 목록은 찾을 수 있다 (데모 박스는 설정의 holders, 모델은 전역 표). 실제로는 서브 랑데부·피어 교환이 필요하고, 이클립스 공격과 함께 "다루지 않음"에 남는다.

## 모델 변경 (`sim/sync.py`, `sim/recon.py`, `sim/oracle.py`, `sim/sync_mc.py`)
- `SyncScene.topics` (0 = CP29–CP30 그대로: 모든 것이 서브 하나), `sub_mode` ("leak" = CP30 박스 그대로: push는 서브 보유자에게, 맞추기·받기는 전부 / "sub" = 고친 것), `d_sub = 3`.
- 서브 가입: 서브 T = 20개, 인기 Zipf(1), 박스마다 1 + Poisson(2)개 (평균 3, 추정). 별도 난수 흐름 (일 흐름은 그대로).
- 글은 쓰는 사람의 서브 중 하나에. 댓글·투표·지우기는 대상의 서브, 대상은 **내가 읽을 수 있는(가입한) 서브의 글** 중에서.
- 일 계수: 검증은 받은 것마다, 인코딩은 내 서브의 글만 (열쇠가 없으면 못 함).
- `recon.TopicKeySet`: 서브별 KeySet + 합집합 보기. `topics = 0`이면 서브 하나라 결과가 CP30과 **같아야 함** (회귀 검사).
- 오라클: **S5 새로 (사전 등록)**: 정직한 박스는 가입 안 한 서브의 메시지를 갖지 않는다. L1/L2는 두 박스가 함께 가진 서브의 키만. 전달 지표(빠짐)는 내 서브의 메시지만. **새 지표 "갇힘"**: 켜진 지 t_bound 넘은 회원 박스가 없는데, 정직한 박스 어딘가(켜짐 무관)에 있는 내 서브 메시지 (작성자만 갖고 꺼져 있는 것 포함).

## 사전 등록 (결과 전)

**예측**: leak는 S5 위반 (H12를 모델이 이제 봄). sub는 S5 0.

**채택 규칙 — sub (S2+KE+sub)를 기본값으로, 아래가 모두일 때**:
1. 층 1 (무작위, 서브 장면 C-a·C-b·C-c × n 10–1000 × 씨앗 1–5, 거짓말쟁이·위조·무효·시계): S1–S5·L1·L2·F1 위반 0.
2. 층 1 전달: 빠짐 ≤ leak + 0.1 % 쌍, 라이브 P99 ≤ leak + 1 s (같은 장면·씨앗). 갇힘: C-a·C-c에서 ≤ leak + 0.1 % 쌍. **C-b(노트북 + 상시 1대)는 보고만**: 비회원 상시 박스가 남의 서브를 들고 있어 주는 것이 leak의 가용성이고, 그건 CP16의 P-sub+k(복제본이 모자란 서브를 박스들이 나눠 맡음)로 따로 다룰 일.
3. 층 2 (대본): CP29·CP30 대본이 topics = 0에서 CP30 결과와 같고, 새 서브 대본이 예측대로.

## 결과

**회귀 (topics = 0)**: CP29·CP30 대본 108개 판정이 CP30과 같음 (예측 밖 1건도 같은 것). 비용 칸 C-b n = 100은 필드까지 같음. 단 아래 모델 버그를 고친 뒤 C-a에서는 바닥 세션이 늘어 오버헤드가 조금 커짐 (n = 100: 32.6 → 38.0 KB/박스·일).

**층 2 서브 대본**: 10번 모두 예측대로. sub는 D1–D5 통과, leak는 D1·D3 실패 (예측), D2·D4·D5는 S5 위반으로 실패 (예측 없음).

**층 3a**: 서브 모형 2,304 상태 위반 0. 돌연변이 `accept_any`, `recon_all+accept_any`(CP29–CP32 박스), `push_any+accept_any`는 S5로 잡힘 (14,720 상태). **`recon_all`, `push_any` 단독은 안 잡힘 → 예측과 다름**: 받는 쪽 거절만으로 S5가 지켜진다. S5 안전성은 받기 검사 하나에 달려 있고, 세션을 거르는 것은 비용(T3) 문제다.

**비용 (모델, 20 서브, 이틀, 씨앗 1–3)**: sub 66칸 위반 0, 중복 0, 오버헤드 최대 51.6 KB/박스·일, 유휴 최대 34.2 KB → 관문 통과. leak(지금 박스)는 오버헤드 최대 352 KB/박스·일 (관문 실패), 라이브 P99 392–1,181 s.

## 찾은 것
- **모델 버그 (CP29~)**: 메시가 D_HI를 넘어 이웃을 자를 때 `up` 표시는 남고 메시에서만 빠져서, 그 이웃이 다시 메시에 들어와도 바닥 타이머가 다시 안 켜졌다 (이미 up이라고 봄). 그 쌍은 접촉 중인데 아무것도 맞추지 않는다 → sub 모드 첫 실행에서 L1 위반 16건으로 드러남. CP30에서는 메시가 작아 드물었다 (그래서 CP30 비용이 약간 낮게 나옴). 진짜 박스는 바닥을 메시가 아니라 up 전체에 돌려서 해당 없음.
- leak(지금 박스)는 서브가 있으면 라이브 P99가 수백 초: push는 서브 회원 이웃에게만 가는데 메시가 서브를 모른다. H12의 두 번째 비용.
- S5는 받기 검사 하나로 지켜진다 (층 3a). 세션 거르기는 비용용.
