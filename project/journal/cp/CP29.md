## 번호가 바뀐 것

## 성질 (결과 전에 적음. 정답은 오라클만 안다)
- **유효성**: 받는 박스가 확인할 수 있는 것만. 서명/증명, 한도, `id = hash(header)`, t_key가 받는 박스의 수용 창 A 안, 지운 표시·잊은 표시 없음. 작성자가 시각을 정직하게 찍었는지는 오라클이 따로 기록한다 (정직한 작성자는 참 시각 ±σ 안에 찍는다는 **가정**). 시각을 속인 효과: 과거로 찍으면 수명이 줄고 now − R보다 오래되면 거부, A 안의 미래로 찍으면 보관이 최대 2σ 늘고, A 밖 미래면 A에 들어올 때까지 거부(수용 지연).
- t_key: 글·댓글·투표는 자기 t0, 지우기는 **대상 글의 t0** (지우기는 대상 헤더를 들고 다니고 대상의 일회용 키로 서명한다).
- 창 (모두 박스 자기 시계 now 기준): 수용 A = [now − R, now + 2σ], 맞추기 대역 B = [now − R + 2σ, now + 2σ], 글은 t_key < now − R이면 버리고 거부, 지운 표시·잊은 ID는 t_key < now − R − 2σ까지 둔다.

| 성질 | 내용 |
|---|---|
| S1 | 정직한 박스는 무효 메시지를 보관·서빙·적용하지 않는다 |
| S2 | 지우기를 적용한 정직한 박스는 대상의 만료 전까지 대상을 다시 보관·서빙·수용하지 않는다 (부활 없음) |
| S3 | 대상의 키로 서명하지 않은 지우기는 적용되지 않는다 |
| S4 | 무효 봉투가 유효 봉투의 수용을 막지 않는다 (선점 없음) |
| L1 | 정직한 a, b가 켜져 있고 링크가 [τ, τ + T_conv(v)] 동안 살아 있으면, τ에 한쪽이 가진 유효 항목 중 그 구간 내내 두 박스의 B 안에 있는 것은 끝에 둘 다 가진다. T_conv(v) = T_trigger + rounds·RTT + v/대역폭. T_trigger: 관찰된 사건 ≈ RTT, 조용히 돌아온 링크 ≤ P_MAX + RTT, 아무도 못 본 손실 ≤ P_AE |
| L2 | L1과 같되 지우기: 둘 다 지운 표시를 갖고 대상을 잊는다 |
| C1 (관문) | 맞추기 한 번의 바이트 ≤ B_fixed + d·(봉투 + c·log₂N). 하루 유휴 바이트 ≤ 예산. CP26 장면의 총 오버헤드 ≤ X2 + 여유 |
| F1 | 보관 ID는 t_key ∈ A, 지운 표시·잊은 ID는 t_key ≥ now − R − 2σ. 그보다 오래된 것은 없다 |

물리적 한계 (위반 아님): 정직한 보유자와 한 번도 (직접이든 사슬로든) 이어지지 않은 박스는 받을 수 없다. 오라클이 도달 가능성을 추적하고 **도달 가능한 빠짐만** 센다. **마지막에 모두 켜는 구간은 없다.**

## 그림 (설계, 결과 전)
```
 받는 길 (S1/S2 공통, H8 고침)
   봉투 ─▶ 검증 (서명·증명, 한도, id = hash(header), t_key ∈ A, 지운/잊은 표시)
            ├─ 실패 ─▶ 벌점 카운트 (CP13), 저장 안 함, 서빙 안 함, ID도 안 넣음
            └─ 통과 ─▶ ID를 집합에 ─▶ 저장 ─▶ 이웃에게 ID 알림 (P2, 응답 확인)
                         └ 대상 모르는 댓글·투표 ─▶ 보류 (서빙 안 함) + 보낸 박스와 맞추기

 고치는 길 (계기는 전부 사건 + 느린 바닥)
   계기 (a) 내가 켜짐/깨어남 → 주제마다 켜진 이웃 전부
        (b) 이웃이 꺼짐/모름 → 켜짐
        (c) 관찰된 전송 실패 (보내기 오류, IHAVE 받았는데 봉투를 끝내 못 받음, 응답 시간 초과) → 그 쌍 dirty, 지수 백오프로 성공까지
        (d) 모르는 ID를 가리키는 항목
        (e) 이웃이 꺼짐 → 남은 이웃과
        (f) 느린 바닥: 켜진 이웃마다 P_AE(10–30분 무작위)에 한 번 지문 비교 (아무도 못 본 손실용)
   ─▶ 맞추기 (집합 = 대역 B 안의 (t_key, id): 보관 메시지 + 잊은 글 ID + 지운 표시)
        S1: 1시간 통마다 해시 → 다른 통의 ID 목록 → 없는 것 가져오기
        S2: (t_key, id) 순 범위 지문(합 mod 2^128 + 개수) → 다른 범위를 16갈래로 쪼갬 → 작으면 ID 목록
   ─▶ 가져온 봉투는 받는 길로

 꺼진 이웃: 지수 백오프로 찔러봄 (상한 P_MAX). 커버리지 주장 없음: 거짓말쟁이는 자기 것만 숨길 수 있고, 정직한 접촉이 고친다
```

## 대안 (결과를 보기 전에 적음)
| | 방식 | 고르면 / 바꿀 조건 |
|---|---|---|
| S0 | 지금 X2 (기준선) | 예측된 실패 (결과 전에 적음): H1, H2, H3, H4 (거짓말쟁이 있을 때), H5 (내놓기 받은 박스가 떠날 때), H8. H6은 지운 표시를 영원히 두므로 **F1 실패, S2는 통과** |
| S1 | 고정 시간 통 (1시간) + 통마다 해시 | 단순. 통 하나가 빽빽하면 비용이 통 크기에 비례해 C1을 못 지킬 수 있음 |
| S2 | 범위 기반 집합 맞추기 (RBSR, Negentropy 꼴) | 차이에 비례. 색인이 필요 (구간 합을 캐시한 트리) |
| S3 | 작성자별 일련번호 (Scuttlebutt 꼴) | **버림**: 한 사람의 글이 연결된다 (CP17 연결 불가능성) |
| 바닥 | S1/S2 각각 바닥 있음/없음 (사건만) | 사건만 변형이 도달 가능한 빠짐을 내고 바닥이 그걸 고칠 때만 바닥을 둔다 |

NORTHSTAR 7-6 시험: 바닥은 "타이머"지만 전체 목록이 아니라 지문 하나(차이 확인)이고, 아무도 관찰할 수 없는 손실(받았다고 응답한 중계 박스가 전달 전에 죽고 그 뒤 아무 일도 없음)은 사건으로 알 방법이 없다. gossipsub의 heartbeat도 같은 이유다. 사건만 변형과 비교해 실제로 고치는 빠짐이 있을 때만 남긴다.

## 판정 규칙 (결과를 보기 전에 적음)
- **값**: R = 1일 (시험용 자리표시. 실제 R은 범위 밖), σ = 120 s, P_AE = 600–1800 s 무작위, 꺼진 이웃 찔러보기 5 s부터 두 배씩 상한 P_MAX = 300 s, dirty 쌍 재시도도 같은 백오프. B_fixed = 256 B, c = 128 B, 하루 유휴 예산 = 박스당 100 KB, 총 오버헤드 여유 = X2 + 5 %p. 봉투 1,000 B, ID 8 B, 헤더 40 B (CP26과 같음, 추정).
- **층별 통과 = 위반 0** (S1–S4, L1, L2, F1). 오라클은 사건마다 S1–S4, F1을 확인하고, 접촉 구간마다 L1/L2 마감을 건다.
- **층 1 (무작위)**: 장면 C-a/C-b/C-c (CP26) + C-0 (상시 박스 없음) + C-x (한꺼번에 50 % 꺼짐), n = 10, 30, 100, 300, 1000, 시드 5. 기능 교차 커버리지: (켜진 쪽: 작성자만 / 보유자만 / 비보유자만 / 아무도 없음) × (사건: 글, 지우기, 댓글) × (결함: 꺼짐, 링크 끊김, 전송 실패, 응답 후 중계 죽음, 분할, 시계 차이, 거짓말쟁이, 무효 먼저). 칸마다 5번 이상 맞거나, 층 2/3이 덮는다고 적는다.
- **층 2 (지정 대본)**: H1–H6, H8, CP26 평가 구멍, 조용한 손실, 조용히 돌아온 링크, 글보다 먼저 온 지우기, 두 창 끝 (now + 2σ 근처로 찍힌 글을 σ 늦은 박스가 받음, 세션 중 B 아래 끝을 넘는 항목), 지운 표시 불변식 (정확한 경계와 ±σ에서 "한 정직한 박스가 지운 표시를 버리는데 다른 정직한 박스가 대상을 받는" 일이 없음. 반대 경우는 시계 한도 위반을 주입했을 때만 돌리고 따로 적음), 과거·먼 미래로 찍은 유효 메시지. S0은 예측한 것만 실패해야 하고 (예측 밖 실패나 예측한 실패의 통과는 그대로 적는다), S1/S2는 전부 통과. 사건만 변형은 조용한 손실에서 실패할 것으로 예측.
- **층 3**: (a) 박스 3개 (하나는 적대 가능), 글 ≤ 2 + 지우기 1 + 댓글 1 + 무효 봉투 1의 BFS 전수 탐색. 주장 범위: "맞추기가 성공할 때 계기 규칙 + 받는 길 + 집합 의미론이 S1–S4, L1, L2를 준다". 반례는 층 2 대본으로. (b) 실제 맞추기 코드 (모델과 데모가 같이 씀) 성질 시험: 크기 0…10^5, 같음/서로소/하나 차이/빽빽한 통/여러 범위/경계 항목, 라운드마다 중단, 세션 중 삽입·만료. 완료 후 합집합 − 잊은 것, 중단 후 손상 없음, 바이트 한도.
- **층 4**: 이 PC에서 박스 4–5개 프로세스, 층 2 대본을 프로세스 죽이기·링크 끊기·시계 차이로. 같은 대본을 모델로. 박스별 칸 (맞추기 세션, 주고받은 ID, 가져온 봉투, 검증·인코딩 횟수)이 모델과 같고, 경쟁 칸만 다를 수 있되 합은 같다. CP24 L1–L7, CP25 P1–P4 통과.
- **고르기**: S1–S4, L1, L2, F1을 모든 층에서 지키고 C1 관문을 넘는 방식이 자격. 자격 중 CP26 장면 n = 10…1000 총 오버헤드가 낮은 것. 20 % 안이면 단순한 S1. 자격이 없으면 무엇이 왜 실패했는지 적고 **데모를 바꾸지 않는다**.
- **칩**: 박스마다 유효 메시지를 한 번씩만 검증·인코딩하는지 **세어서** 확인 (가정 아님). 거짓말쟁이가 준 무효 항목 때문에 더 한 검증을 센다. 따라잡기 몰림 모양이 바뀌면 CP28 밀린 수집 숫자를 다시 본다.
- 순서: 층 1–3과 비용을 모델로 먼저. 데모 박스 (층 4)는 **팀 기준선 실행이 끝난 뒤** 바꾼다 (실행 중 코드가 바뀌면 기준선이 깨짐).

## 계획에서 달라진 점 (결과를 보기 전 / 본 뒤를 나눠 적음)
- **결과 전 (스모크·성질 시험 뒤)**:
  - 바닥: 쌍의 두 박스가 각자 돌리던 타이머를 "그 쌍이 P_AE 안에 맞췄으면 건너뜀, 다음 확인은 마지막 맞추기 + P_AE"로. 간격은 여전히 ≤ P_AE.
  - S2 갈래 수 8 (계획에 수가 없었음). 갈래 16은 1만·10만 집합의 하나 차이에서 C1을 0.4%·5% 넘어서 (층 3b).
  - 실패한 후보 박스도 찔러보기 (최대 D_HI개, 1시간). 계획의 "꺼진 이웃 찔러보기"를 모델이 덜 구현했던 것 (H5 사건만 변형에서 드러남).
- **결과 본 뒤, 고쳐서 다시 돌림 (설계 구멍, 표시)**:
  - 대상 글이 대역 B 밖인 댓글이 영원히 보류되어 두 박스가 같아지지 못했다 (n = 100 스모크의 L1 367건). → 대상을 모르는 댓글·투표도 집합에 넣고 전달, 화면에만 안 보임.
  - 메시 차수가 줄지 않고 커졌다 (평균 13, 최대 18). → D_HI를 넘으면 D로 쳐냄 (gossipsub).
  - **H9**: 작성 시각 t0가 서명 범위 밖이었다 (`Msg.header()`). 중계 박스가 서명을 깨지 않고 시각만 바꿀 수 있었다. → t0와 지우기의 대상 헤더를 서명 범위에.
  - **H10** (층 4에서 발견): 서명 검증 캐시가 id만 키로 썼다. 서명만 깨진 사본(같은 내용 → 같은 id)이 먼저 오면 진짜가 검증 없이 거부됐다. 검증 후 저장으로 막은 선점이 캐시로 살아 있었던 것. 층 1–3 모델에는 캐시가 없어서 못 봤다. → 캐시 키 (id, 서명).
  - 데모의 "조용한 손실" 훅이 조용하지 않았다 (ID 먼저 push가 1초 뒤 다른 알린 박스에 다시 물음). → "받았다고 믿고 잃음"으로.
  - 회귀: 슬래싱 알림이 내용 id 때문에 발견한 박스마다 따로였다 (L6 알림 2개). → 키·nonce·시각(시간 단위)을 a0에서 정해 같은 시간대의 알림은 같은 메시지. 데모의 위반 흉내(`/api/misbehave`)는 저장하지 않고 봉투로 내보냄. 시험 장치 P3는 recon이면 내용 id와 ref로 메시지를 만듦.
- **규모**: 층 1의 n = 1000은 S0과 S2만, 시드 1–2 (한 번에 20–40분; S1은 C1에서 탈락, 바닥 규칙은 n ≤ 300으로 판단). 앞서 시작한 전체 그리드에서 끝난 n = 1000 사건만 변형 5개(위반 0)는 `logs/cp29_random_first5.log`.
- **색인**: 계획은 "구간 합을 캐시한 균형 트리 O(log N)". 구현은 바뀐 뒤 첫 조회에서 접두합을 O(N)으로 다시 만든다 (10만 개 38 ms, 예비). 바꿀 조건: 박스 색인이 10⁵를 넘을 때.

  - ③ 조항이 비교하는 X2(S0)는 같은 장면에서 L1을 수천~수억 번 어긴다. "틀린 프로토콜보다 5 %p 이상 비싸지 않을 것"은 좋은 기준이 아니었다.
  - 그리고 ③은 고정 비용(바닥·찔러보기, 박스당 하루 수십 KB)을 글 수에 비례하는 비율로 쟀다. 그래서 글이 적을수록 무조건 실패한다.
  - 정확성은 S2만 갖췄다. 비용은 위의 새는 곳 셋을 짜낸 뒤, 절대량(박스·하루 바이트)과 꼭 받을 바이트 대비를 함께 보는 관문으로 다시 사전 등록해서 잰다.

## 교훈
- 사건만으로는 아무도 못 본 손실을 고칠 수 없고, 상시 박스가 많을수록 이 손실이 남는다 (노트북은 자주 켜져서 저절로 고쳐진다). 반대로 바닥의 비용은 글이 적을수록 크게 보인다.
- 모델 층은 프로토콜 규칙의 구멍을 잡고, 진짜 코드 층은 구현의 구멍을 잡는다. 서명 캐시(H10)는 층 1–3이 볼 수 없는 곳이었다.
- 내용 해시 id는 "id = 메시지"를 만들지만, id가 덮지 않는 것(서명, t0)은 따로 묶어야 한다 (H9, H10).
