# CP35 — 연결 정책 대 칩: 틀린 증명 홍수를 프로토콜이 막으면 검증 유닛이 필요한가 (D-a)

- 형식: **목적형**. [디자인] [구현] [측정 (모델)]
- 시작: 2026-11-18. 근거: `journal/recast/REVIEW.md` 2a, `LEDGER.md` D1, NORTHSTAR 7-7 (대안을 같은 방식으로 잰다).
- 이 문서의 "사전 규칙"과 "예측"은 결과를 보기 전에 썼다. 결과를 본 뒤 바꾼 것은 **(결과 뒤)**로 표시한다.

## 문제

- CP19는 틀린 증명 홍수의 크기를 "링크 속도(100 Mbps, 초당 12,207개)"로 잡고, 그걸 버티라고 검증 유닛 6×6을 골랐다 (규칙 V).
- 그때 견준 연결 정책은 둘이었다.
  - N-b는 연결당 틀린 증명 10개 뒤 끊기 + IP당 새 연결 0.2/s다. 모델로 쟀고, IPv4 주소 6,104개면 링크 속도에 닿는다.
  - N-c는 박스 전체의 모르는 연결 상한이다. **측정 없이** "새 사용자 합류를 막는다"로 기각했다 (CP19.md:64–66).
- 외부 정찰(가설)의 지적:
  - 정직한 박스는 검증한 뒤에야 중계한다 (CP17 F5). 그래서 틀린 증명 하나면 그 연결은 악의다.
  - 첫 번에 끊고 모르는 연결에 상한을 걸면, CPU로 버틸 수 있지 않나.

## 설계하다 찾은 것 (결과 전)

**칩은 연결 핸드셰이크를 가속하지 않는다.**
- 새 연결 하나에 호스트가 X25519 셋 + Ed25519를 한다. 0.57 ms (CP19 예비 측정 × Pi 5 2.93)다.
- 그래서 공격자가 증명 대신 **새 연결 시도**로 홍수를 내면, 칩 박스도 호스트가 먼저 무너진다.
  - 계산: 2코어 / 0.57 ms ≈ 초당 3,500 연결 (추정).
- 결론: 두 세계 모두 모르는 연결에 상한 A가 필요하다. 새 박스 합류 문제(N-c를 기각한 이유)는 **칩이 있어도 똑같이** 생긴다.
- 따라서 공정한 대결은 "상한 없는 칩 박스 대 상한 있는 CPU 박스"가 아니다. **같은 연결 정책 아래에서 검증을 어디서 하느냐**다.

```
                 공격자 (주소·키 무제한, IPv6)
        연결 시도 λ_a/s ──────────────┐
                                     ▼
 ┌──────────────── 홈 박스 (Pi 5급 호스트 4코어) ─────────────────────┐
 │  ① 아는 이웃(메시·전에 맞는 글을 준 상대) ──▶ 상한 없이 통과       │
 │  ② 모르는 연결: 토큰 A/s ── 넘치면 핸드셰이크 전에 버림 (c_rej)    │
 │        └─ 받은 연결: 핸드셰이크 0.57 ms (호스트, 칩 불가)           │
 │  ③ 받은 모르는 연결은 첫 증명이 맞을 때까지 메시지 1개만 (credit 1) │
 │        └─ 틀리면 끊기 ─ 공격자는 받은 연결당 틀린 증명 1개          │
 │  검증:  W-cpu = 호스트 CPU 4.07 ms × W3  |  W-chip = 검증 유닛 6×6  │
 └────────────────────────────────────────────────────────────────────┘
 새 박스: 후보 k개 중 3개에 붙어야 합류. 그중 φ는 공격받는 중 → 받아 줄 확률 A/(A+λ_a)
```

## 대안 (같은 박스, 같은 공격자, 같은 연결 정책)

| 세계 | 검증 | 연결 정책 | 비고 |
|---|---|---|---|
| **W-cpu** | 호스트 CPU, 틀린 증명 하나 4.068 ms × W3 (CP12 A76 추정, `sim_cp20.CPU_SINGLE`) | N-d = ① + ② + ③ | 외부 정찰이 말한 대안 |
| **W-chip** | 검증 유닛 6×6 (CP14, `sim_cp19.V_BAD`) | N-d. 단 칩에 유리하면 ③ 대신 N-b(연결당 10개)도 허용, 더 나은 쪽을 쓴다 | 지금 설계 |
| 참고 R0 | 검증 유닛 6×6 | CP19 N-b 그대로 | CP34 `chip_w16` S4 재현 (같은 틀 확인) |

- 공통 입력 (모두 추정. 이 CP에서 새로 정한 가정은 ★):
  - 호스트: Pi 5 4코어 (CP19 `Box`, `sim_cp24.fixed` 호스트).
  - 인코더: CP34 16×16 FP16 (`encoder_resize_w16` 비율, `chip_w16`과 같은 방식).
  - 정직한 트래픽: 10⁶명 커뮤니티의 상위 박스 (CP16 P-all, CP19 S4와 같음). 검사 순서는 O-b(증명 먼저).
  - 핸드셰이크: 0.57 ms (CP19).
  - ★ c_rej: 상한을 넘어 핸드셰이크 전에 버리는 시도 하나의 호스트 비용. 기본 10 µs, 민감도 2·50 µs. 출처 없음, 가정이다 (커널 SYN 쿠키 + accept/close의 자릿수).
  - ★ λ_a: 공격자의 연결 시도 속도 ∈ {10², 10³, 10⁴, 10⁵}/s. 상한은 링크다: 100 Mbps를 74 B SYN으로 채우면 약 1.7×10⁵/s (추정: 100e6 / (74 × 8)).
  - ★ 새 박스 합류:
    - 후보 k = 10 (작은 서브의 회원), 그중 공격받는 비율 φ ∈ {0.5, 0.9, 1.0}, 붙어야 할 수 D = 3.
    - 공격받는 박스에 한 번 시도하면 받아 줄 확률은 A/(A + λ_a)다. 토큰이 부족할 때 무작위로 받는다고 본다.
    - 거절은 RST로 0.1 s 뒤에 안다. 그다음 후보로 넘어가고, 후보를 다 돌면 다시 처음부터 돈다.
    - 성공한 연결은 끊기지 않는다.
  - 상한 A 격자: {1, 3, 10, 30, 100, 300, 1000, 3000, 10⁴}/s.

## 사전 규칙 (결과 전)

- **K 기준** (CP19 LIMITS 그대로): K1 정직한 텍스트 P99 ≤ 4.64 s, K2 검색어 P99 ≤ 50 ms, K4 호스트 제공 코어 ≤ 2.0, K5 칩 ≤ 2 W. 60 s 공격 구간, 시드 3.
- **A\*(λ_a, φ)**: 새 박스 합류 P99 ≤ **J = 60 s** (소유자 결정)를 지키는 가장 작은 A (격자). 몬테카를로 10⁴번.
- **칸 판정** (λ_a, φ마다, 세계마다): A\*가 있고, 그 세계의 박스가 A\*에서 K1·K2·K4(·K5)를 지키면 그 칸 통과.
- **D1 결정**:
  - W-chip이 통과하는 모든 칸에서 W-cpu도 통과하면 → **검증 유닛의 폭주 필요성 없음** (연결 정책이 대신함). 중간 보고서 표 IV의 주장이 틀린다.
  - W-chip만 통과하는 칸이 있으면 → 필요성은 그 칸들(λ_a, φ 범위)로 **좁혀진다**. 보고서는 그 범위만 주장한다.
  - 둘 다 못 지키는 칸 → 칩과 무관한 **연결 홍수 문제**로 기록한다 (LEDGER 새 의심).
- **첫 번에 끊기 오탐**:
  - 모델에서는 정직한 메시지가 정의상 맞으므로 오탐을 볼 수 없다.
  - 대신 진짜 박스 시험(기준선 오라클 실행)의 정직한 대본에서 증명 거절 수를 센다. 결함을 주입한 대본의 의도된 거절은 뺀다.
  - 0이 아니면 ③을 "k번째에 끊기"로 바꾸고 다시 돈다.
  - 회원 루트·epoch 창은 박스에 아직 없다. 그래서 "받는 쪽이 최근 루트 몇 개를 받아 줘야 한다"를 N-d의 **요구사항**으로 적고, 측정한 척하지 않는다.
- **같은 틀 확인**: R0이 CP34 `cp34_chip.json`의 S4(호스트 코어, 칩 W)를 5% 안에서 재현해야 결과를 믿는다.

## 예측 (결과 전, 셈)

- 받은 모르는 연결 하나의 호스트 비용 (추정):
  - W-cpu: 0.57 + 4.07 × W3 ms ≈ 4.7 ms. K4(2코어)까지 A ≈ 420/s.
  - W-chip: 0.57 ms. A ≈ 3,500/s.
- 칩은 상한을 약 8배 높게 둘 수 있게 해 준다. 그것 말고 다른 차이는 없다.
- φ ≤ 0.9: 새 박스는 공격받지 않는 후보로 합류한다. A와 거의 무관하게 두 세계 모두 통과할 것이다.
- φ = 1 (후보 전부 공격):
  - 합류에는 받아 줄 확률이 대략 A/(A+λ_a) ≳ 0.15 정도 필요하다 (거절 0.1 s, 60 s에 시도 약 600번이라 실제로는 더 낮아도 됨).
  - λ_a = 10²–10³에서는 W-cpu도 통과할 것이다.
  - λ_a = 10⁴에서는 W-chip만 통과할 수 있다.
  - λ_a = 10⁵에서는 c_rej × λ_a = 1코어라 둘 다 위험하다.
- 그래서 예상 판정은 **"좁혀짐"**이다. 범위는 φ = 1이고 λ_a가 10³–10⁴ 사이의 어딘가다.

## 계획에서 달라진 점

- **스모크 뒤, 전체 실행 전** (2026-11-18): λ_a 격자에 3×10³, 3×10⁴를 더했다 (→ {10², 10³, 3×10³, 10⁴, 3×10⁴, 10⁵}).
  - 이유: 스모크는 칸 세 개(시드 1, 10 s)의 부하만 봤다. 그 부하는 위 예측 셈과 같았다 (W-cpu A = 100에서 0.49코어).
  - 그런데 예측대로라면 "칩만 통과" 띠는 10⁴과 10⁵ 사이에 있다. 격자가 그 띠를 건너뛸 수 있었다.
- 증명 홍수는 링크 속도(12,207/s)를 넘지 않게 잘랐다. W-chip이 연결당 10개(N-b)를 쓸 때 A × 10이 링크를 넘는 칸이 생겨서다.

- **결과 뒤 (표시)**: 모델 실수를 하나 고치고 다시 돌렸다.
  - 실수: W-chip이 연결당 10개(N-b)를 쓰는 칸에서 증명 수를 링크 속도로 자르면서, **핸드셰이크 수까지 같이 줄였다** (핸드셰이크를 증명 10개마다 셈).
  - 최악의 공격자는 토큰 A개를 모두 쓰고, 증명은 그 연결들에 나눠 링크만큼만 보낸다. 고친 뒤에는 핸드셰이크를 받은 연결 수 min(A, λ_a)만큼 따로 센다.
  - 영향: λ_a = 10⁵ 두 칸이 "칩만 통과"에서 **"둘 다 실패"**로 바뀌었다. 나머지 칸은 같다.
  - 첫 실행 결과는 `logs/cp35_duel_first_run.json` (git 제외)에 남겼다.

## 결과 (모델, 추정)

**같은 틀 확인 통과**: R0(CP19 N-b, 칩, 링크 속도)이 CP34 S4를 그대로 재현했다 (칩 0.9898 W, 검증 유닛 바쁨 0.8455, 호스트 0.85코어).

**합류**: A\*는 λ_a의 약 3%다. φ = 0.5면 A = 1로도 된다 (공격 안 받는 후보로 합류). φ ≥ 0.9면 A\* = 3, 30, 100, 300, 1,000, 3,000이다 (λ_a = 10², 10³, 3×10³, 10⁴, 3×10⁴, 10⁵). 예를 들어 λ_a = 3×10⁴, φ = 1에서 합류 P99는 A = 300일 때 85 s, A = 1,000일 때 25.5 s다.

**A\*에서의 박스 (φ ≥ 0.9, c_rej 10 µs, 시드 3)**

| λ_a (/s) | A\* (/s) | W-cpu 호스트 코어 | W-cpu K | W-chip 호스트 코어 (첫 번에 끊기 / N-b) | W-chip K | 칸 |
|---|---|---|---|---|---|---|
| 10² | 3 | 0.04 | 통과 | 0.01 / 0.01 | 통과 | 둘 다 |
| 10³ | 30 | 0.18 | 통과 | 0.03 / 0.03 | 통과 | 둘 다 |
| 3×10³ | 100 | 0.53 | 통과 | 0.09 / 0.10 | 통과 | 둘 다 |
| 10⁴ | 300 | 1.54 | 통과 | 0.27 / 0.31 | 통과 | 둘 다 |
| **3×10⁴** | 1,000 | **5.01** (새 글 P99 28 s) | K1·K4 실패 | 0.87 / 0.99 | 통과 | **칩만** |
| 10⁵ | 3,000 | 15.1 | 실패 | 2.71 / 2.83 | **K4 실패** | **둘 다 실패** |

- φ = 0.5에서는 모든 λ_a에서 둘 다 통과한다 (A\* = 1).
- **c_rej 민감도** (A\*에서): 50 µs면 W-chip도 λ_a = 3×10⁴에서 2.03코어로 실패한다 → "칩만" 띠가 없어진다. 2 µs면 W-chip이 λ_a = 10⁵에서 1.93코어로 통과한다 → 띠가 10⁵까지 넓어진다. W-cpu는 c_rej와 상관없이 3×10⁴에서 실패한다 (4.8–6.2코어).

**판정 (사전 규칙): D1 = 좁혀짐.**
- 검증 유닛이 필요한 경우는 다음 셋이 **모두** 성립할 때뿐이다.
  - 공격자가 새 박스 후보의 90% 이상을 동시에 친다.
  - 박스마다 초당 1만–10만 번 사이의 연결을 시도한다. 격자에서는 3×10⁴ 칸 하나다.
  - 핸드셰이크 전 거절 비용이 수십 µs 아래다.
- 그 밖에서는 연결 정책 N-d를 쓴 칩 없는 Pi 5가 K1·K2·K4와 합류 60 s를 지킨다.
- 초당 10만 번이면 칩이 있어도 못 버틴다: 핸드셰이크와 거절이 호스트를 먹는다. 이건 칩이 아니라 연결 수락의 문제다 (LEDGER D7).
- 칩이 하는 일은 결국 이것 하나다: **받은 모르는 연결 하나의 호스트 비용을 4.9 ms에서 0.57 ms로 줄여, 상한 A를 약 8배 높게 둘 수 있게 한다.**
- 중간 보고서 표 IV("Pi 5는 14–37코어가 필요하다")는 **연결 상한이 없을 때**의 숫자다. 최종 보고서에는 이 조건을 붙인다.

**첫 번에 끊기 오탐 (측정, 진짜 박스 4대)**:
- 리캐스트 기준선 오라클(`recast` 브랜치 = main `c339de2`)의 `sync_check` 14대본에서 셌다.
- 증명 거절(`rej_bad_proof`)은 **0**이다.
- 거절은 위조 사본을 일부러 넣은 대본(H8) 하나의 `rej_id` 1, `rej_bad_sig` 1뿐이다.
- 단, 박스의 증명은 RLN을 흉내 낸 것이고 회원 트리·루트가 없다. 그래서 "받는 쪽이 최근 루트 몇 개를 받아 준다"는 N-d의 요구사항으로 남는다 (측정 안 됨).

## 결론

- **D1 = 좁혀짐** (사전 규칙). 칩 없는 Pi 5 + N-d는 다음을 지킨다: 공격자가 새 박스 후보의 절반만 칠 때는 모든 λ_a에서, 거의 다 칠 때도 λ_a ≤ 10⁴/s까지.
- 검증 유닛이 있어야 하는 띠는 λ_a ≈ 3×10⁴/s, φ ≥ 0.9이고, c_rej에 민감하다.
- 칩의 몫은 "받은 모르는 연결의 호스트 비용 4.9 → 0.57 ms" 하나다.
- 칩과 무관하게 남는 것: λ_a = 10⁵/s 연결 홍수 (D7), c_rej 측정 (D8).
- 갈림길 F에 넘길 것: 검증 유닛의 폭주 필요성은 "좁혀짐"이다. 최종 보고서는 이 띠만 주장하고, 표 IV에 "연결 상한이 없을 때"를 붙인다.
- CP38에 넘길 것: N-d의 "아는 이웃" 표는 서브별 이웃 다시 붙기와 같은 자료다. CP38에서 함께 설계한다.
