# CP40 — 10⁷ 추천 검증 대결: 전원이 다 검증(칩) / 내 피드에 닿는 것만 늦게 검증 / 집계 증명

- 형식: **목적형**. [디자인] [측정 (모델·셈)]. 하드웨어 필요를 주장할 수 있는 CP라서 프로토콜 대안과의 측정한 대결을 포함한다 (CLAUDE.md 1, NORTHSTAR 7-6·7-7).
- 상태: **계획, CP37 ① 뒤** (2026-11-18 소유자: 평판 증명이 먼저). 사전 규칙을 먼저 적고, 이 문서가 커밋된 뒤에 돌린다.
- 출발점 (CP39 B1, 추정, **정정 반영**):
  - ② 아래 10⁷에서 박스가 받는 메시지의 대부분이 추천 묶음이다 (CP16 BASE 평균 초당 27.7개 중 24.7개, 높은 띠 138개 중 123개).
  - 추천 메시지 하나마다 증명과 머리 400 B가 붙는다.
  - **BASE에서는 10⁷이 예산 안이다.** 업로드·한 달 양 실패는 높은 띠(활동 ×5)에서만 나고, 거기에 추천 바이트가 들어 있다.
  - 계산은 작다 (높은 띠에서 검증 = 칩의 2.0%, Pi 5 한 코어의 23%).
  - 그래서 이 CP는 **높은 띠를 장면으로** 잰다 (소유자: 높은 띠의 10⁷만 새 요구).

## 답할 질문
- 10⁷에서 추천을 어떻게 검증하면 바이트와 계산이 예산 안에 들고, 새 신뢰를 들이지 않는가?
- 그때 칩은 필요한가?

## 세 안 (합리화 테스트 6 순서: "모두가 같은 계산을 반복" → 덜 하기 → 한 번만 하기 → 그다음에 하드웨어)

| 안 | 무엇 | 의심하는 것 |
|---|---|---|
| (b) 늦은 검증 | 추천은 다 받는다. 검증은 내 피드 순위에 영향을 주는 것만 한다: 내 후보 글(상위 k)에 붙은 추천, 그리고 순위를 바꿀 수 있는 추천. 나머지는 검증 안 된 채 세지 않는다 | 계산은 줄지만 바이트는 그대로다. 위조 추천이 검증 전까지 순위에 끼는지 |
| (c) 집계 증명 | 아무 박스나 집계자가 된다. 한 기간(epoch) 동안 글 하나에 온 추천을 모아 "중복 없는 nullifier를 가진 유효 추천 N개"의 증명 하나와 nullifier 목록(또는 그 해시 트리)을 낸다. 나머지 박스는 증명 하나만 검증한다. 기준 방법: SnarkPack(Groth16 증명 n개를 로그 크기로 묶음, Gailly·Maller·Nitulescu, FC 2022), 해시 트리 + 재귀 증명 | 집계자가 추천을 빼먹는 검열(안전은 증명이 지킴, 생존은 아님). 집계자의 증명 생성 비용 |
| (a) 전원이 다 검증 | 지금 설계. 모든 박스가 모든 추천 증명을 검증한다 (칩) | 기준선. 칩 필요는 (b)·(c)가 둘 다 실패할 때만 선다 |

## 재는 것 (10⁷, 바쁜 시간, CP16 행동 모델 ×10, CP39 B1과 같은 조건)

| 번호 | 지표 | 어떻게 |
|---|---|---|
| M1 | 박스당 추천 바이트 (다운·업), 검증/s, Pi 5 코어 몫, 칩 바쁜 몫 | 셈. (c)는 집계 하나의 크기·검증 시간을 출처나 측정으로 |
| M2 | 피드 정확도 (공격 아래) | 모델: 박스 피드 상위 50에서 표시된 추천 수가 참값(유효 추천 수)과 1% 넘게 다른 글의 몫. 공격 = 신원 10⁴개가 틀린 증명 추천 / 이중 추천을 한도 끝까지 |
| M3 | 추천이 순위에 반영되기까지 P99 | 모델 |
| M4 | 새 신뢰 | (c): 추천을 집계자 m곳에 보낼 때, 정직한 추천이 어떤 집계에도 안 들어갈 확률. 집계자가 위조할 수 있는가 (증명으로 막히는지 확인) |
| M5 | 집계자 비용 | (c): 집계 증명 생성 시간 (CPU 측정 또는 출처). 박스가 집계를 돌아가며 맡을 때의 박스당 하루 몫 |

## 사전 규칙
- 한 안이 "통과" = 아래를 모두 지킴.
  - **M1**: 추천 바이트를 더한 10⁷ 업로드가 CP39 예산(2 Mbps)을 넘게 만드는 몫을 줄인다. 칩 없이 검증이 Pi 5 한 코어 안이다.
  - **M2**: 공격 아래 상위 50 오차 ≤ 1%.
  - **M3**: P99 ≤ 60 s (J, CP35와 같은 값).
  - **M4**: 안전에 새 신뢰가 없다 (위조 불가). 검열에 걸릴 확률 ≤ 10⁻³ (m 선택 포함).
- 고르기:
  - (b)·(c) 중 통과하는 가장 싼 안 (M1 + M5 합)을 기본값으로 한다.
  - 둘 다 실패하면 (a)를 기본값으로 하고, 칩의 검증 몫을 이 CP의 측정으로 주장한다.
  - (c)가 집계자 증명 생성 때문에만 실패하면, 그 생성(MSM)을 CP37 ①과 같은 칩 후보로 올린다.
- 모델과 실물을 합치지 않는다. 박스 코드는 762203b 그대로 12-06까지 둔다 (소유자). 이 CP는 모델·셈·벤치뿐이다.
