## ① 평판 증명 먼저 (2026-11-18 소유자: CP40보다 먼저. 결과 전에 적음)

**왜 지금 첫째인가 (CP39)**:
- ② 아래에서는 스팸이 모든 박스에 간다. 정직한 한도를 지키는 신원 100개만으로 10⁶에서 글의 77%가 스팸이다.
- 박스가 저장·인코딩·피드 전에 "추천 영수증 N개 이상"을 증명한 글만 올리는 입구가 있어야 한다.
- 그래서 재는 것이 둘로 늘었다.
  - 작성자의 생성 비용 (원래 ①).
  - 모든 박스의 글마다 검증 비용 (② 때문에 새로 생김).

**회로 REP-N (`bench/crypto_bench/src/bin/rep.rs`, BN254 Groth16, CP23과 같은 손 Poseidon)**:
- 영수증 잎 j = H(a0, r_j) (a0 = 신원 비밀, r_j = 영수증마다 다른 값). 깊이 20 영수증 트리에 대한 Merkle 경로 N개, 같은 공개 뿌리.
- 같은 영수증을 두 번 세지 못하게, 잎 위치(경로 비트로 만든 수)가 엄격히 증가함을 20비트 범위 검사로 보인다.
- 신원 묶기: 공개 태그 = H(a0, 외부 nullifier). RLN과 같은 a0이라 증명끼리 이을 수 없다.
- 회원 경로는 RLN 증명이 이미 한다. 이 회로는 영수증만 본다.
- 영수증을 누가 어떻게 발급하는지(투표 → 작성자 영수증)는 이 측정 밖이다. 설계 빈칸으로 남긴다.

**재는 것 (이 PC = 세컨컴, Core Ultra 9 185H "IT13 Max", 전원 오버레이 최고 성능, G-Helper 없음, 단일 스레드 arkworks 0.5)**:
- N ∈ {1, 10, 100}: 제약 수, setup 시간, 증명 생성 시간, 검증 시간, 증명 + 공개 입력 바이트, 증명 키 크기.
- 기계 기준선:
  - CP6 제곱 사슬 2^16 증명 생성을 이 PC에서 다시 잰다. 랩톱(CP6) 3,436 ms와의 비 q를 구한다.
  - Pi 5 = 랩톱 × 2.93 (CP34). 그래서 Pi 5 시간 = 이 PC 시간 / q × 2.93 (추정).
  - 이 PC는 CP23을 잰 PC다. cp23을 다시 돌려 제약 수가 같고 검증이 3% 안임을 확인했다 (공용 가젯 분리 뒤).

**가늠 (CP37 틀: 판정 대신 배수)**:

| 번호 | 무엇 | 목표 | 넘으면 |
|---|---|---|---|
| G1 | 작성자: Pi 5에서 글 하나에 REP-N 생성. 단일 코어와, 4코어 이상적 분할(÷4, 추정 상한) 둘 다 | K1 5 s | 넘는 배수를 갈림길 F의 "새 워크로드" 후보로 (MSM, CP10 곱셈기 재사용 정도와 함께) |
| G2 | 모든 박스: 글·댓글마다 REP 검증 1번 더 (또는 RLN에 합침). 박스당 Pi 5 코어 몫, CP39 B1 장면 (10⁶·10⁷, BASE·높은 띠) | 호스트 1% 미만이면 무시 | 칩 검증 유닛 몫으로 셈 |
| G3 | 칩 셈: Groth16 생성의 G1 MSM 크기 → Pippenger Fq 곱 수 (셈) → CP10 곱셈기(300 MHz, 곱 4사이클) 6개 시간 | | NTT는 Fr 위라 지금 RTL로 못 함 (CP37 원래 표) |

**G1 (작성자)**:
- N = 10은 4코어로 나누면 K1 안이다 (1.7 s). 1코어면 1.3배 넘는다.
- N = 100은 4코어로도 2.8배 넘는다 (13.9 s).

**G2 (모든 박스, 글·댓글마다 REP 검증 1번)**: Pi 5 코어 몫.

|---|---|---|---|

- 칩 검증 유닛이면 0.2% 미만이다.
- 스팸도 버리려면 하나씩 검증해야 한다. 신원 10⁴개(오래된 한도)면 초당 100개, Pi 5 코어의 32%다. 칩이면 0.7%다.

**G3 (칩, 사전 규칙: G1 MSM만)**:
- G1 MSM 넷의 Fq 곱은 N = 100에서 4.6억 번이다 (Pippenger 셈). CP10 곱셈기 6개로 1.02 s다.
- 그래도 G2 MSM과 FFT가 호스트에 남는다. 그래서 Pi 5 + 칩은 1코어 25.8 s, 4코어 7.2 s다. K1의 1.45배로 아직 넘는다.
- N = 10은 4코어 0.97 s, 1코어 3.4 s로 K1 안이다.

**결과 뒤 추가 셈 (표시)**:
- G2 MSM은 Fq2 산술이다 (Fq2 곱 = Fq 곱 3번). 검증 유닛은 이미 페어링을 위해 Fq2·Fq12를 Fq 곱셈기로 계산한다. 그래서 같은 곱셈기로 G2 MSM도 돌릴 수 있다고 보고 셈했다.
- 이러면 호스트에 FFT만 남는다. Pi 5 + 칩: N = 100에서 1코어 4.99 s, 4코어 2.59 s다 (G2 MSM 칩 0.77 s). N = 10에서 4코어 0.32 s다.
- 이 셈은 사전 규칙(G3)에 없던 것이다. RTL 재사용 정도(제어·메모리)는 안 쟀다.

**가늠 결론 (CP37 틀)**:
- **평판 증명 생성은 갈림길 F의 "새 워크로드" 후보다.**
  - 넘는 배수: N = 100에서 Pi 5 4코어 2.8배, 1코어 11배.
  - 칩 재사용: G1 MSM은 지금 Fq 곱셈기를 그대로 쓴다 (사전 규칙 셈: 7.2 s, 아직 1.45배). G2 MSM까지 같은 곱셈기로 하면 K1 안이다 (결과 뒤 셈: 2.6 s). FFT(Fr)는 호스트에 남는다.
- **검증은 새 일이 아니다.** 검증 유닛이 이미 하는 Groth16 검증이 하나 더 붙는다. ②의 10⁷과 스팸 상황에서는 칩 몫이 된다.
- **쓸 만한 N은 아직 모른다.**
  - N이 작으면 Pi 5만으로 된다 (N = 10, 4코어).
  - N이 커야 스팸을 막는다면 칩이 필요하다.
  - 그래서 다음 조각은 "N이 스팸을 얼마나 막나"(모델)다. 신원이 영수증을 얻는 속도와 산 추천(CP39 R5)을 넣는다.

## ① 다음 조각: 영수증 몇 개(N)가 스팸을 막나 (모델, 결과 전에 적음)

**질문**: 피드 입구를 "영수증 N개 이상"으로 막을 때, 어떤 N과 어떤 영수증 규칙이 스팸을 막으면서 정직한 새 회원을 너무 오래 막지 않나. N이 정해지면 칩이 필요한지가 정해진다. 위 ①: Pi 5 4코어는 N ≈ 36까지 K1 5 s 안이다 (추정: 13.9 s × N/100 = 5).

**모델 (`experiments/rep_gate.py`, 하루 단위, 사용자 2만 명 표본, 90일, 씨앗 3)**:
- 행동: CP16 BASE (`sim/community.py`).
  - 활성 26%, 쓰는 사람 10%.
  - 활성 사용자당 하루 글·댓글 0.10, 추천 0.82 (글 하나에 평균 8.2표).
  - 쓰는 양은 로그정규 꼬리 1.85.
- 새 회원: 하루 1% (가정). 처음 있던 사람은 "창립 회원"이다.
- 입구: 글을 쓸 때 작성자의 **인정 영수증**이 N개 이상이면 피드에 오른다. 아니면 "새 글 칸"에 간다.
  - 새 글 칸의 글은 피드 글보다 ρ = 0.2배로 추천을 받는다 (가정).
  - 추천은 글 품질(로그정규 σ 1, 가정)에 비례해서 받는다.
  - 정직한 사람은 스팸에 ε = 0.01배로만 실수 추천한다 (가정).
- 영수증 규칙 셋 (추천한 사람이 "인정되는" 조건):

| 규칙 | 인정 조건 |
|---|---|
| any | 아무 신원 |
| age | 가입 30일 이상 (CP22 나이 그룹과 같은 생각) |
| rep | 창립 회원이거나, 자기도 인정 영수증 N개 이상 (전이) |

- 공격 셋. 신원 K = 사용자의 1% (10⁶에서 10⁴과 같은 비율). 0일에 들어온다. 글은 정직한 한도 끝까지 낸다 (CP22 오래된 한도 864/일).

| 공격 | 무엇 |
|---|---|
| 혼자 | 서로 추천하지 않음 |
| 고리 | 공격 신원끼리 모든 글에 서로 추천 (글 하나에 신원마다 한 표) |
| 고리 + 산 표 | 신원마다 인정 표를 한 번 B = N개 산다 (정직한 인정 계정에서) |

- N ∈ {1, 3, 10, 30, 100}.

**재는 것 (60–90일 평균)**:
- 피드에 오른 글 중 스팸 몫.
- 정직한 새 회원 중 쓰는 사람이 처음 피드에 오르기까지 걸린 날 (중앙값), 그리고 30일 안에 오른 몫.
- 산 표 공격에서 공격자가 산 표의 총수.

**사전 규칙 (문턱은 가정)**:
- (규칙, N)이 "작동" = 고리 공격에서 피드 스팸 ≤ 5%, 그리고 정직한 새 작성자 대기 중앙값 ≤ 7일, 그리고 30일 안 통과 ≥ 90%.
- 산 표 공격은 보고만 한다 (산 표의 값은 신원 비용 문제, NORTHSTAR 5).
- 칩 판정: 작동하는 가장 작은 N이 36 이하면 평판 증명 생성은 Pi 5로 된다. 넘으면 칩 후보가 선다 (위 G1·G3 숫자로).
- 작동하는 조합이 없으면 그대로 적는다: "영수증 입구만으로는 고리를 못 막는다 → 신원 비용이 먼저".

**스모크 뒤, 전체 실행 전 (표시)**:
- 스모크 (씨앗 1, N = 10, 고리): 세 규칙 모두 피드 스팸 99.6%. 새 작성자 30일 통과 5–8%.
- 문제 1: 실수 추천을 "스팸 글 하나에 ε배 무게"로 넣었더니, 스팸 글이 정직한 글의 200배라 공격자 1%가 정직한 추천의 약 3분의 1을 가져갔다.
  - "정직한 사람은 1%만 실수로 스팸을 추천한다"는 뜻과 다르다.
  - **둘 다 돌린다**: `weight`(사전 규칙 그대로)와 `share`(정직한 추천의 ε = 1%가 스팸에 감, 스팸 사이에서는 노출 비례). 판정은 사전 규칙대로 `weight`로 하고, `share`는 보고한다.
- 문제 2: 쓰는 양의 꼬리(1.85)가 길어서 새 작성자 대부분이 한 달에 두 번도 안 쓴다. 입구가 없어도 "가입 뒤 30일 안 피드" 기준을 못 넘는다.
  - **기준을 바꾼다**: 대기 = 첫 글부터 처음 피드에 오른 글까지. 30일 통과 = 가입 30일 안에 글을 쓴 새 작성자 중, 첫 글 뒤 30일 안에 피드에 오른 몫.
  - 입구 없음(N = 0) 기준선을 같이 보고한다.
- 문턱(스팸 5%, 대기 7일, 통과 90%)은 그대로다.

## ① 다음 조각 결과 (모델, `results/chip/cp37_rep_gate.json`, 씨앗 3)

- 실행 중 고친 버그: 새 회원 배열 크기를 평균 가입 수로 잡아서, 포아송 가입이 평균을 넘으면 넘쳤다. 여유를 1.5배로 두고 처음부터 다시 돌렸다.

| 모드 | 규칙 | 공격 | N = 1 | N = 3 | N = 10 | N = 30 | N = 100 |
|---|---|---|---|---|---|---|---|
| weight (사전 규칙) | 모두 | 모두 | 스팸 99.5% | 99.5% | 99.6% | 99.6% | 99.7% |
| share (스모크 뒤) | any | 혼자 / 고리 | 99.5% | 99.5% | 99.4% / 99.5% | 94.6% / 99.6% | **0%** / 99.6% |
| share | age | 혼자 / 고리 | 99.4% / 99.5% | 99.4% / 99.5% | 98.8% / 99.5% | **3.5%** / 99.6% | **0%** / 99.7% |
| share | rep | 혼자 / 고리 | 99.5% | 99.5% | 99.2% / 99.5% | 41% / 98.1% | **0% / 0%** |
| share | rep | 고리 + 산 표 | 99.5% | 99.5% | 99.5% | 99.6% | 99.7% |

정직한 새 작성자 (첫 글부터 처음 피드에 오를 때까지; 입구 없음 N = 0이면 0일, 통과 100%):

| 모드 | N = 1 | N = 3 | N = 10 | N = 30 |
|---|---|---|---|---|
| weight | 18–32일, 30일 통과 49–60% | 61일 이상, 26–39% | 못 오름, 9–14% | 2–4% |
| share | 10–22일, 61–74% | 19–35일, 46–61% | 못 오름, 25–34% | 10–16% |

**판정 (사전 규칙)**:
- 작동하는 (규칙, N)이 없다.
- 고리 공격에서 피드 스팸 ≤ 5%를 지킨 것은 share 모드의 rep·N = 100 하나뿐이다. 그때 정직한 새 작성자의 30일 통과는 3%다.
- 규칙대로 적는다: **"영수증 입구만으로는 고리를 못 막는다 → 신원 비용이 먼저"**.
- 칩 판정: 쓸 N이 정해지지 않았다. 평판 증명 생성이 칩 후보인지는 미정으로 남는다.

**왜 (숫자에서 본 것)**:
1. **한 신원의 정직한 한도(864/일)가 정직한 실제 양(활성 사용자당 0.1/일)보다 너무 크다.**
   - 공격자 1%가 한도 끝까지 내면, 스팸이 정직한 글의 약 330배다 (추정: 0.01 × 864 / 0.026, 규모와 무관).
   - 피드 스팸 5% 이하를 지키려면 공격 신원의 약 0.016%만 통과해도 넘는다. 사실상 한 명도 통과하면 안 된다.
2. **입구는 신원 단위의 예/아니오다.** 한 신원이 한 번 통과하면 하루 864글이 피드에 오른다.
3. **전이 규칙(rep)은 한 명이 뚫리면 다 뚫린다.** 공격자 하나가 실수 추천으로 N에 닿으면, 그의 표가 인정되어 고리 전체가 하루 만에 통과한다 (share·rep·고리 N = 30: 98.1%). 산 표 공격은 모든 N에서 통과다.
4. **정직한 새 작성자에게는 N = 1도 비싸다.** 대부분 한 달에 두 번도 안 쓰고, 새 글 칸은 추천을 0.2배만 받는다. N = 1에서도 피드까지 중앙값 10–32일이다.

**이 결과가 가리키는 다음 (재지 않음, 후보)**:
- 신원 비용 (NORTHSTAR 5, 1순위 그대로).
- **글쓴이별 피드 상한**: 한 피드에 한 작성자의 글을 하루 m개까지만 보여 준다. ②에서는 각 박스가 자기 피드를 직접 만들므로 운영자 없이 할 수 있다. 330배 물량을 신원 수로 줄인다.
- **정직한 한도를 실제 쓰는 양에 맞추기**: CP22의 한도는 정직한 거부 10⁻³에 맞춘 것이다. 거부를 조금 더 받아들이고 한도를 낮추는 맞바꿈.
- 보는 사람마다 다른 신뢰 (내가 추천한 사람의 추천만 센다). 증명으로 만들기 어렵다.

## ① 남은 후보 넷 (소유자 "완료해줘", 결과 전에 적음)

같은 모델(`experiments/rep_gate.py`)에 손잡이 넷을 넣는다. 사전 규칙의 문턱(피드 스팸 ≤ 5%, 새 작성자 대기 중앙값 ≤ 7일, 30일 통과 ≥ 90%)은 그대로다. 실수 추천은 두 모드 다 돌린다.

| 손잡이 | 무엇 | 값 |
|---|---|---|
| m 작성자별 피드 상한 | 피드는 한 작성자의 글을 하루 m개까지만 보여 준다 (②에서 각 박스가 자기 피드를 만든다). 추천도 보이는 글에만 간다 | ∞, 10, 3, 1 |
| L 하루 한도 | 한 신원이 하루에 낼 수 있는 글·댓글 (CP22는 864) | 864, 50, 10 |
| K 공격 신원 몫 | 신원 비용이 얼마나 줄여 줘야 하는지를 거꾸로 잰다 | 1%, 0.1%, 0.01% |
| 보는 사람 신뢰 (viewer) | 보는 사람마다, **자기가 추천한 적 있는 사람**의 추천만 센다. 자기가 추천한 적 있는 작성자는 바로 보인다. 표본 보는 사람 300명 | N ∈ {1, 3} |

- 규칙 셋(any, age, rep)과 N ∈ {0, 1, 3, 10}, 공격 셋(혼자, 고리, 고리 + 산 표).
- **L의 대가**: 정직한 글 중 한도에 걸려 못 나가는 몫. CP22의 정직한 거부 기준 10⁻³을 문턱으로 같이 본다 (넘으면 그 L은 쓸 수 없음).
- **K 판정**: 각 (규칙, N, m, L)이 작동하는 가장 큰 K = 신원 비용이 공격 신원을 그 아래로 눌러야 하는 선.
- **viewer**:
  - 판정 지표는 보는 사람별 피드 스팸 몫의 평균과 상위 10% 보는 사람이다.
  - 새 작성자는 "첫 글 30일 안에 보이게 된 보는 사람 몫"으로 보고만 한다 (보는 사람마다 다르게 보이는 설계라 통과 기준이 다르다).
- 결론 규칙:
  - 작동하는 조합이 있으면 가장 싼 것(N이 작고, m·L 제약이 덜한 것)을 기본 후보로 적는다. 그 N으로 칩 판정을 낸다 (N ≤ 36이면 Pi 5).
  - 없으면 "어떤 K까지 버티는가"를 신원 비용의 요구로 적는다.

## ① 남은 후보 넷 결과 (모델, `results/chip/cp37_rep_knobs.json`, 3,024칸 × 씨앗 3)

- 확인: 손잡이를 기본값에 두면 앞 실행(`cp37_rep_gate.json`)과 숫자가 같다 (weight·rep·고리·N = 10: 스팸 0.996, 새 작성자 통과 0.0890).
- 작동 칸: 143개.
  - 전역 규칙(any·age·rep)에서는 **모두 N = 0 (영수증 입구 없음) + 작성자별 상한 m**이다.
  - 나머지는 viewer 규칙이다.

**1. 작성자별 피드 상한 m이 주 손잡이다** (영수증 없음 N = 0, L = 864, 고리 공격; weight / share):

| m \ 공격 신원 몫 K | 1% | 0.1% | 0.01% |
|---|---|---|---|
| 상한 없음 | 99.5% / 99.5% | 95.2% / 94.9% | 64.5% / 66.1% |
| 10 | 70.6% / 70.3% | 19.3% / 19.7% | **2.3% / 2.4%** |
| 3 | 46.1% / 47.0% | 7.8% / 7.9% | **0.8% / 0.8%** |
| 1 | 29.6% / 30.0% | **4.1% / 4.1%** | **0.4% / 0.4%** |

- 새 작성자: 입구가 없으니 대기 0일, 통과 100%.
- 영수증 입구를 더해도 스팸이 줄지 않는다. 새 작성자만 막힌다 (rep N = 3, m = 1, K = 0.1%: 스팸 4.4%, 30일 통과 0.655).

**2. 한도 L 낮추기는 못 쓴다.**
- 정직한 글 중 거부 몫: L = 50이면 0.26%, L = 10이면 6.8%다 (쓰는 양 꼬리 1.85). CP22 문턱 10⁻³을 넘는다.

**3. 신원 비용의 요구 (K 판정)**:
- m = 1이면 공격 신원이 회원의 **0.1% 이하**일 때 피드 스팸 ≤ 5%다 (10⁶에서 10³개). m = 3이면 0.01% 이하일 때 작동한다.
- 신원 비용(NORTHSTAR 5)이 이 선 아래로 눌러야 한다.

**4. viewer (보는 사람 신뢰)**:
- 피드 기준은 통과한다. N = 3, m ≤ 3이면 K = 1%에서도 스팸 평균 ≤ 0.9%, 상위 10% 보는 사람 ≤ 3.3%다.
- 그러나 **새 작성자가 거의 안 보인다.** 첫 글 30일 안에 보이게 된 보는 사람 몫의 중앙값이 0–0.3%다 (N = 3), N = 1이어도 2.3% 이하다.
- 또 "누가 누구를 추천했나"를 보는 사람이 알아야 해서, 추천의 익명성(RLN으로 서로 이을 수 없음)과 부딪힌다.

**판정 (사전 규칙)**:
- 작동하는 가장 싼 조합은 **N = 0 + 작성자별 상한 m = 1 (하루 한 글이 피드 몫), 한도 그대로**다. 공격 신원 ≤ 0.1%까지 버틴다.
- 칩 판정: N = 0이라 평판 증명 생성이 필요 없다. **평판 증명 생성은 이 설계에서 칩 후보가 아니다** (앞의 "F 후보" 가늠을 거둔다).
- viewer는 규칙상 작동하지만 새 작성자가 사실상 안 보이고 익명성과 부딪힌다. 공개 글 층의 기본으로는 안 쓴다. 친구 피드 같은 선택 기능 후보로 적는다.

**설계 메모 (재지 않음)**:
- 작성자별 상한은 익명으로도 걸 수 있다. "피드 자리" 전용 RLN 기간(하루, 한도 m)을 두면 된다. 박스는 글끼리 잇지 않고도 한 신원이 하루 m개보다 많은 피드 자리를 쓰면 막을 수 있다 (CP17·CP23 RLN 그대로). 검증은 지금 검증 유닛 일과 같다.
- 남은 1순위는 신원 비용이다: 공격 신원을 회원의 0.1% 아래로 누르는 것.
