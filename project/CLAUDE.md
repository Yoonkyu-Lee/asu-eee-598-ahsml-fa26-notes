# 연구 파이프라인 지침 (project/)

EEE 598 파이널 프로젝트: **server-blind 커뮤니티의 엣지 노드를 위한 가속기.**
원래 아이디어와 제안서는 `archive/topic-selection/` (IDEA.md, SPEC.md, 제안서 pptx).
**작업 전에 [NORTHSTAR.md](NORTHSTAR.md)를 읽는다.** 무엇을 하든 그 문서와 이어지는 이유를 댈 수 있어야 한다. 에이전트에게 위임하거나 외부 평가를 받을 때도 NORTHSTAR.md를 함께 넘긴다.
이 폴더의 모든 작업은 아래 규칙을 따른다. 예외 없음.

## 1. 단위: 체크포인트 (CP)

- CP 하나 = **큰 문제 하나**를 푼다. 작은 계획 여러 개가 모여 CP 하나가 된다. 잡일이나 작은 단계 하나를 CP로 만들지 않는다.
- CP는 둘 중 하나로 시작한다. 시작할 때 어느 쪽인지 적는다.
  - **목적형**: 답할 질문이 분명하다.
  - **정찰형**: 아이디어를 얻으려는 사전 답사다. "정찰"이라고 명시하고, **무엇을 가늠하는지**를 적는다.
- 무엇을 하는지는 **구현 / 측정 / 디자인 / 데모 / 조사** 중 어느 것인지 표시한다.
- CP가 하드웨어의 필요를 주장하면, 그 CP는 프로토콜 대안과의 **측정한 대결**을 포함한다 (NORTHSTAR 7-7).

## 3. CHECKPOINT.md 항목 양식

```
## CPn — <제목>   (상태: 계획 / 진행 / 완료, 날짜)
- **테마**: 한 줄
- **목적**: 목적형이면 목적. 정찰형이면 "정찰: <무엇을 가늠하는지>"
- **무엇을 하나**: [구현]/[측정]/[디자인]/[데모]/[조사] 표시한 불렛
- **답할 질문**: 불렛
- **계획과 이행**: 간결 요약 + `cp/CPn.md` 링크 + 아티팩트 링크
- **기대 → 실제 → 교훈**: 간단 요약 (세부 숫자는 cp/CPn.md)
- **계획에서 달라진 점**: before → after (있을 때만)
- **다음 CP**: 제목과 한 줄 목적
```

## 5. 측정과 숫자

- 숫자는 **측정값 / 출처 인용 / (추정: 계산식)** 중 하나로 표시한다. 지어내지 않는다.
- 로컬 시간 측정 전에는 사전 점검을 먼저 기록한다: AC 전원, Windows 전원 계획, G-Helper 모드, `nvidia-smi` 전력 제한, 다른 GPU 사용 프로세스. 사용자가 확인하지 않은 조건에서 잰 숫자는 **예비 측정**으로 표시한다.
- 사용자가 GPU로 무언가를 돌리는 중이면 GPU를 쓰지 않는다.

## 6. 파일과 공개

- 구조 (CP31): 최신 결론에 필요한 것만 위에, 지난 것은 `legacy/`. 무엇이 어디인지는 [README.md](README.md)의 폴더 표.
  - `chip/` 칩 (rtl, model — **최신 칩 숫자는 `chip/model/chip.py` 하나에서만**), `box/` 노드 박스, `sim/` 프로토콜·시뮬 공용, `bench/` 워크로드 측정, `experiments/` 결론 재현, `tests/` 진짜 박스 시험, `docs/` 설계서.
  - 결과 JSON은 `results/<chip|sync|bench|tests|그 CP의 주제>/`. CP 번호 폴더를 새로 만들지 않는다.
  - CP 문서는 `journal/`. 새 CP 스크립트는 주제 폴더에 역할 이름으로 둔다 (`sim_cpNN.py` 식 이름 금지). 결론에서 빠진 코드는 `git mv`로 `legacy/`에 옮기고 `legacy/README.md` 표에 적는다.
  - 옛 CP 문서의 명령은 태그 `cp30`에서 재현된다 (CP31에서 옮김).
  - 논문 PDF는 `refs/`(git 제외).
- 실행 로그(콘솔 출력)는 `logs/cpN_<무엇>.log`(git 제외). 루트에 두지 않는다. 숫자는 로그가 아니라 `results/`의 JSON과 CP 문서에 남긴다.
- 논문 PDF, pptx, 과제 파일은 공개 저장소에 올리지 않는다. 커밋 전에 무엇이 올라가는지 확인한다.
- 새 변이 플래그를 넣을 때는 **은퇴 조건**(어떤 결과가 나오면 지우는지)을 CP 문서와 `LEDGER.md` Decisions에 함께 적는다. 비교용으로 남길 변이는 코드에 두지 않고 태그로 보내며, 재현 명령은 그 태그에 묶는다 (예: `git worktree add ../cpNN cpNN` 뒤 그 안에서 실행).
- 칩·프로토콜 숫자를 문서에 손으로 옮기지 않는다. 숫자는 결과 JSON → `chip/model/chip.py` → 문서 순으로 흐르고, `tests/fast/`의 검사가 셋이 같은지 본다.
- 데이터셋(BEIR 등)은 `data/`(git 제외)에 둔다.

## 7. 연구 코드의 리캐스트 규칙 (2026-11-18)

출처: 리캐스트 규칙 (`yt-frame-analyzer/northstar/AGENTS.md` 1–23, `WORKFLOW.md`). 뺀 규칙과 이유는 `journal/recast/DRAFT_CLAUDE.md`.

목표: 코드는 (1) CP가 답할 질문이나 NORTHSTAR 불변식을 지키고, (2) 측정된 자원 안에 있고, (3) 신뢰 경계(박스의 네트워크 입력)를 지키는 만큼만 자란다. 그 밖의 코드는 지울 후보다.

**바꾸기 전**
1. 바꾸는 코드가 어느 CP 질문·주장·불변식을 위한 것인지 한 줄로 말한다. 못 대면 멈추고 묻는다.
2. 버그는 원인을 먼저 적고, 지우거나 합치는 고침을 먼저 찾는다. 특수 경우를 더할 때는 지우는 고침이 왜 없는지 적는다.

**바꾸는 동안**
3. 두 번째 실제 사용 전에는 추상화하지 않는다. 가정은 이름 붙은 상수로 둔다.
4. 입력 검사는 신뢰 경계(박스 HTTP·동기화 입력)에서만 한다. 시뮬레이터 안에서는 자기 함수를 믿는다.
5. 속도를 위해 코드를 늘리면 전후 측정을 CP 문서에 남긴다. 견고성을 위해 늘리면 먼저 실패하는 시험을 만든다.
6. **변명 주석 금지.** 땜질·재시도·타이머·"임시" 경로를 정당화하거나 미루는 주석(workaround, for now, in case, TODO 등)을 쓰지 않는다. 원인을 고치거나, `LEDGER.md` Doubts에 올리고 소유자에게 묻는다.

**의심 → 대결 → 고정**
7. 전제·대안·땜질·비용에 대한 의심은 `LEDGER.md` Doubts에 한 줄로 적고, **측정한 대결이나 소유자 결정으로만** 닫는다. 지금 코드가 왜 괜찮은지 설명하는 것은 닫는 것이 아니다.
8. 새 파일이나 큰 증가 전에 기준 방법(이 저장소의 기존 코드, 표준 라이브러리, 잘 알려진 방법, 진짜 도구)과 크기·의도 벤치마크를 견준다. 결과를 CP 문서에 `Alternatives:`로 적는다.
9. 같은 종류의 결함이 두 번 나오거나 같은 지적을 두 번 받으면, 글이 아니라 가장 싼 기계 검사(시험, import 금지, 숫자 대조)로 막는다. `Ratchet:`으로 적는다.
10. 근거(`Evidence:`)는 실제로 돌린 것이다: 명령 출력, 결과 JSON, 화면.

**시험**
11. 리캐스트 조각은 오라클을 **원본에 먼저** 돌리고, 조각마다 결과 JSON의 판정이 같은지 본다. 숫자가 비트 단위로 같을 필요는 없지만 다르면 기록한다.
12. 리캐스트는 브랜치에서 한다. **전체 오라클**(층 2·3a, `sync_check`, L1–L7, P1–P4, 무대 15/15)을 통과한 조각만 main에 병합한다.
13. 버그 고침은 고치기 전에 실패하는 시험과 함께 한다. 고친 줄을 되돌려 다시 실패하는지 확인한다 (돌연변이 검사).
14. 리뷰 지적은 말로 기각하지 않는다. 불가능함을 보이는 시험으로 기각하거나 소유자에게 올린다.
15. **모델(sim)과 실물(box)을 하나로 합치지 않는다.** 실물이 모델을 검증하는 오라클 가치를 잃는다. 대신 같은 대본에 같은 판정이 나오는지 자동으로 비교한다.

**게이트 (G-a, 2026-11-18)**: `tests/fast/`에 변명 주석 검사, 숫자 대조, legacy import 금지를 두고 커밋 전에 돌린다. gate.py 전면 도입(INTENT/TRACE 포함)은 학기 뒤(G-c).

**동결**: 발표 데모와 최종 보고서 코드는 **2026-12-06**에 동결한다. 그때까지 전체 오라클을 통과하지 못한 리캐스트 조각은 브랜치에 남기고, 보고서에는 결과만 쓴다.
