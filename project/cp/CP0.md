## 방법
1. 1강 "Top Conferences in Our Community" 슬라이드의 학회만 허용: ISCA, MICRO, ASPLOS, HPCA, MLSys / DAC, ICCAD, DATE, ASP-DAC / ISSCC, VLSI, ESSCIRC, CICC / NeurIPS, ICCV, CVPR, ICML, AAAI.
2. 갈래 셋(A 검색·인코더, B 암호·프라이버시, C 온디바이스 ML 시스템)을 하위 에이전트 3개에 병렬로 맡김. 조건: 학회·연도를 DBLP/ACM/IEEE/학회 페이지로 확인, 공개 PDF 링크, 초록에 있는 숫자만 사용.
3. 18편 PDF를 `refs/cp0/`에 내려받고 1쪽 제목이 맞는지 직접 확인 (18/18 일치).
4. 한 편(IKS)을 전문 읽고 수업 리뷰 양식으로 리뷰: `refs/cp0/IKS review yoonkyul.txt`.
5. 팀원용 영어 목록: `refs/cp0/HANDOUT.md`.

## 18편 브리핑 (목적 / 결과 / 우리에게)

### A. 검색과 인코더
| 논문 | 목적 | 결과 (초록 기준) | 우리에게 |
|---|---|---|---|
| A1 NDSearch, ISCA'24 | 그래프 ANN 검색을 SSD 플래시 안(LUN 병렬)에서 | CPU 대비 처리량 최대 31.7배, GPU 대비 14.6배 | 인덱스가 DRAM을 넘으면 저장장치 가까이에서 검색 + 다음 이웃 미리 읽기 |
| A2 IKS, ASPLOS'25 ★리뷰 | RAG는 정확 검색이 낫다 → CXL 근접 메모리 가속기 | 정확 검색 13.4–27.9배 (결론부는 18–52배로 다름) | 정확 검색 + 작은 top-K 유닛. 우리 규모면 검색 자체는 싸다는 근거 |
| A3 LEANN, MLSys'26 | 임베딩을 저장하지 않고 검색 때 재계산 | 인덱스 크기 최대 50배 감소, 정확도 유지 | 저장 공간 ↔ 인코더 연산 트레이드오프 실험 축 |
| A4 RoCR, ICCAD'24 | 엣지 기기 개인 데이터 RAG를 CiM으로 | 노이즈 강건 임베딩 학습 (초록에 수치 없음) | **우리와 가장 가까운 엣지 검색 하드웨어.** 저정밀 유사도의 노이즈를 학습으로 흡수 |
| A5 EdgeBERT, MICRO'21 | 엣지 BERT를 지연 목표 안에서 최소 에너지로 | 에너지 최대 7배 절감, TX2 GPU 대비 53배 | 수집(백그라운드)과 쿼리(대화형)에 다른 지연 예산 + early exit + DVFS |
| A6 SpAtten, HPCA'21 | 어텐션 토큰·헤드 가지치기 + O(n) top-k 엔진 | DRAM 접근 10배 감소, GPU 대비 162배 | top-k 엔진, 상위 비트로 먼저 거르고 경계만 정밀 재계산 |

## 답
- **팀원 3명에게 한 편씩** (추천): EdgeBERT(인코더·전력, 수집 경로), NDSearch(메모리·저장장치 계층), PipeZK(익명 신원의 암호 커널). 내가 리뷰한 IKS가 네 번째. 각자 관심사에 맞춰 바꿔도 됨.
- **Gap 문장은 유효하지만 좁혀야 한다.** 엣지 검색 하드웨어(RoCR, ICCAD'24)는 이미 있다. 18편 중 누구도 다루지 않은 것은 "새 게시물을 마감 안에 검증·복호화·임베딩·삽입하는 수집 경로"와 "검색 중 삽입"이다 (IKS도 이 실험이 빠져 있음). 단, 18편 범위에서의 결론이다.

## 교훈
- IKS Table 3: 정확 검색 시간의 약 99.9%가 메모리 스캔, top-K 병합은 µs 단위. 우리 인덱스는 최대 약 384 MB (추정: 10⁶ × 384 B)라 노트북 DRAM에서 스캔 한 번이 수 ms일 것 → **쿼리 경로보다 수집 경로(인코더)가 병목일 가능성.** CP1에서 측정으로 확인.
- 같은 논문 안에서도 수치가 다를 수 있다 (IKS 초록 vs 결론). 인용 전에 본문 표를 확인한다.
