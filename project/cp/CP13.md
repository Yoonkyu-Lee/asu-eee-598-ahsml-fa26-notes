# CP13 — 배치를 깨는 폭주

2026-11-01 시작. 요약은 [CHECKPOINT.md](../CHECKPOINT.md), 그림은 아키텍처 보드(L1 "틀린 증명이 섞인 폭주")와 체크포인트 보드.

## 왜 이 CP인가
CP11–CP12의 폭주 숫자(24,862 증명/s, 칩 0.48 W)는 **들어오는 증명이 전부 맞다**는 가정 위에 있다.
- 배치 검증은 무작위 가중치를 건 페어링 곱 하나로 n개를 한 번에 확인한다. 틀린 증명이 하나라도 섞이면 배치 전체가 실패한다 (CP6에서 확인).
- 공격자에게 맞는 증명은 비싸다 (RLN 정체성 + 증명 생성, 속도 제한을 넘기면 비밀키가 드러남). **틀린 증명은 공짜다** (임의의 곡선 위 점 세 개면 형식 검사와 부분군 검사를 통과한다).
- 그러니 가장 싼 공격은 틀린 증명을 섞는 것이다. 배치가 계속 깨지면 처리량이 단건 검증 수준으로 무너진다.

NORTHSTAR 4 "스팸이 수집 자원을 고갈시키지 않아야 한다"를 칩 수준에서 직접 시험한다.
- 형식: **목적형**. [구현] [디자인] [조사].
- 답할 질문: 틀린 비율 f ∈ [0, 1]에서 검증 유닛(곱셈기 5 + 덧셈기 4, CP11)이 100 Mbps(초당 12,207개)를 다 가려내나? 못 한다면 가장 싼 해법은 전략, 하드웨어, 네트워크 층 중 무엇인가?

## 그림 (설계, 결과 전)
```
 네트워크 ──▶ 디코딩·부분군 검사 (증명당 한 번, 결과 256 B 보관) ──▶ 배치 n개 시험 ──통과──▶ n개 모두 수락
   폭주 12,207/s                     형식이 틀린 것은 여기서 버림           │실패
   그중 비율 f가 틀린 증명                                                ▼
                                                     어느 증명이 틀렸나 찾기 (전략 A–D)
                                                       ├ 맞는 것 → 수락 (정직한 글은 하나도 버리지 않는다)
                                                       └ 틀린 것 → 버림 + 보낸 연결에 벌점 (네트워크 층, 전략 밖)

 시험 1번의 비용 (Fp 곱 수, CP11 기록기로 다시 셈)
   배치 k개 = 고정 F (공개 입력 MSM, α, 준비된 3쌍 Miller loop, 최종 지수승) + k × 증명당 b
   단건     = 디코딩을 뺀 단건 검증 (CP11: 44,175 곱 중 디코딩 제외분)
```

## 대안 (찾기 전략, 하드웨어는 CP11 그대로)
| | 전략 | 무엇을 보관하나 | 실패한 배치를 어떻게 푸나 |
|---|---|---|---|
| A | 하나씩 | 디코딩 결과 | 배치가 실패하면 n개 모두 단건 검증 |
| B | 반으로 나누기, 다시 계산 | 디코딩 결과 | 반씩 다시 배치 시험 (왼쪽이 통과하면 오른쪽은 시험 없이 바로 나눔) |
| C | 반으로 나누기, Miller 값 보관 | 디코딩 결과 + 증명마다 Miller loop 값 (Fp12, 384 B) | 실패한 뒤에 증명마다 Miller 값을 한 번 만들고, 부분 시험은 보관한 값의 곱 + 고정 F만 |
| D | 크기 조절 | B 또는 C | 최근 실패율로 다음 배치 크기 n을 고름 (f가 크면 n = 1 = 단건) |

배치 크기 n ∈ {8, 16, 32, 64, 128}. 마이크로코드는 서로 독립인 시험 여러 개를 CP11처럼 나란히(lock-step) 돌린다고 둔다 (이용률은 CP11 배치의 증명당 이용률). 민감도: 한 번에 시험 하나 (CP11 단건 이용률).

하드웨어 대안 (전략으로 모자랄 때): 곱셈기 M ∈ {5, 6, 7, 8, 10} (CP10 합성 0.283 mm²씩). 덧셈기 A도 함께 바꿈 (아래 "계획에서 달라진 점").

네트워크 층 대안 (칩 밖): 틀린 증명을 보낸 연결을 끊고, 새 연결의 수락 속도를 제한한다 (gossipsub v1.1 peer scoring, Waku RLN-relay). 그러면 틀린 증명의 속도는 공격자가 새 연결을 만드는 속도로 묶인다. 이 CP에서는 출처를 찾아 **칩이 견디는 틀린 비율 f_max가 네트워크 층에 요구하는 숫자**로만 적는다.

## 판정 규칙 (결과를 보기 전에 적음)
지표: 가려내는 용량 = 초당 끝까지 분류(수락 또는 버림)하는 증명 수. 정직한 증명은 버리지 않는다.

- **D1 전략**: f ∈ [0, 1] 전체에서 최저 용량이 가장 큰 전략. 5% 안에서 같으면 보관 SRAM이 작은 쪽.
- **D2 하드웨어**: D1 전략의 최저 용량이 12,207/s 미만이면, 이를 지키는 가장 작은 M을 고른다. 단 검증 유닛 면적 ≤ 3.66 mm² (CP12의 2배)이고 폭주 중 칩 ≤ 2 W일 때만. 아니면 M = 5를 두고 D3로.
- **D3 네트워크 층**: 고른 구성에서 100 Mbps를 지키는 최대 틀린 비율 f_max와, 그때 네트워크 층이 묶어야 하는 틀린 증명 속도(초당 몇 개)를 적는다. 항상 적는다.
- **R3 지연**: 폭주 중 맞는 증명이 수락될 때까지 더해지는 지연 P99 ≤ 1초 (새 글 5초 안에 검색 가능의 몫).

뒤집을 조건:
- S1: 단건 시험이 배치의 증명당 비용의 2배 미만이면 배치의 이득이 작다 → 배치를 빼고 단건만 두는 마이크로코드 단순화를 제안한다.
- S2: 전략 C의 보관 메모리가 64 KB를 넘으면 C를 버린다 (CP12 검증 유닛 SRAM 40 KB 기준).
- S3: 출처로 네트워크 층(peer scoring 등)이 노드 하나에 들어오는 틀린 증명을 f_max × 12,207/s 아래로 이미 묶는다고 확인되면, D2의 하드웨어 추가는 하지 않는다.

- 시험 종류별 Fp 연산 수는 CP11 기록기로 셈. 배치 시험은 크기 4·8로 고정분과 증명당분을 나누고, 16에서 맞춰 봄 (곱 178,260 기록 vs 178,884 맞춤, 0.4% 차이).

### 네트워크 층 (조사, 출처는 아래)
- 출처에서 **노드 하나에 들어오는 틀린 메시지 속도의 숫자 상한은 찾지 못했다.**
- gossipsub v1.1: 검증을 통과한 메시지만 전달한다. 그래서 틀린 증명은 직접 연결된 이웃에게서만 온다. 틀린 메시지는 P4 벌점 (카운터의 제곱, 상한 없음), 점수가 graylist 기준 아래면 그 연결의 RPC를 무시한다. (출처: libp2p specs gossipsub-v1.1.md)
- nwaku (Waku RLN-relay 구현): 틀린 증명 → Reject → P4. 가중치 −100, graylist −10,000, `disconnectBadPeers = true`. 증명은 하나씩 검증한다 (배치 없음). (출처: logos-delivery relay.nim, protocol.nim)
  - (추정: −100 × c² ≤ −10,000 → 연결 하나가 c = 10개를 보내면 끊김. 토픽 가중치 1로 둠.)
- 새 연결 속도: go-libp2p 리소스 매니저는 IPv4 /32마다 초당 0.2개, IPv6 /56마다 0.2개·/48마다 0.5개, 전체 상한은 없음 (출처: go-libp2p conn_rate_limiter.go). nim-libp2p(nwaku)는 찾지 못함.
- (추정) M5A4의 f_max 0.06 = 초당 틀린 증명 730개 → 연결 73개/s → IPv4 주소 366개 (또는 IPv6 /48 146개)가 있으면 넘긴다. 주소가 많은 공격자에게는 네트워크 층이 막아 주지 못한다.
- **S3: 안 걸림** (숫자 상한의 출처 없음).

### 판정
- **D1: 전략 D (크기 조절) + B (반으로 나누기, 다시 계산).** C와 최저점이 같고(단건) 보관 SRAM이 작다. 맞는 증명이 대부분이면 n = 64–128, 틀린 비율이 1%면 16, 3–15%면 8, 20%를 넘으면 단건.
- **D2: 곱셈기 8 + 덧셈기 8.** 검증 유닛 2.69 mm² (CP12의 1.47배, 한도 2배), 폭주 중 칩 1.33 W (한도 2 W). 칩 전체 11.0 → **11.9 mm²**.
- **D3:** M5A4는 f_max 0.06 (초당 틀린 증명 약 730개). M8A8은 f = 1에서도 지킴 → 네트워크 층에 기대는 숫자가 없다.
- S1: 단건이 배치 증명당의 3.2배 (시간), 3.1배 (에너지) → 2배 넘음, 배치는 남긴다. S2: C의 보관은 n=128에서 48 KB (64 KB 미만)지만 D1에서 이미 빠짐. S3: 안 걸림.

## 해석
1. CP11의 "폭주의 2배" 여유(R2 = 24,414/s)는 맞는 증명만 올 때의 이야기였다. 틀린 증명만 보내는 공격에서는 배치가 무의미해지고, 필요한 여유는 단건/배치 비율인 **3.2배**다.
2. 단건 시험의 비용은 거의 전부 고정 비용 F (최종 지수승 + 검증키 Miller loop)다. 그래서 찾기 전략(B, C)을 아무리 다듬어도 단건 아래로는 못 내려간다. 하드웨어를 정하는 것은 **F의 크기**다.
3. F는 덧셈이 곱의 3.7배다. 곱셈기만 세던 CP8–CP10 모델로는 보이지 않던 부분이다.
4. 우리 모델은 cyclotomic 제곱을 일반 Fp12 제곱으로 세서 F를 부풀렸다 (CP11 단순화). 최종 지수승의 제곱 대부분이 cyclotomic이므로, 이것을 줄이면 M8A8이 6–7개로 줄어들 수 있다 → 다음 CP 후보.
5. 네트워크 층의 벌점은 연결 하나의 몫을 묶을 뿐, 주소가 많은 공격자를 막지 못한다. 칩이 f = 1을 견디는 것이 불변식 4를 지키는 가장 단단한 방법이다.

## 한계
- 전부 모델. 단건 처리량은 독립 시험을 나란히 돌리는 마이크로코드를 가정함. 한 번에 하나씩 돌리면 M5A4에서 단건 시험만으로 50,235사이클 (디코딩을 빼고도 5,972/s, 나란히 돌릴 때보다 20% 넘게 낮음).
- D의 n은 f를 아는 것으로 고름 (상한). 실제로는 최근 실패율로 추정하고, 공격자가 f를 갑자기 바꾸면 몇 배치 동안 손해 (모델에 없음).
- 곱셈기·덧셈기를 늘릴 때 피연산자 레지스터 파일의 포트와 크로스바 비용은 넣지 않음. 덧셈기 면적은 Aladdin 256비트 덧셈기 2개.
- 틀린 증명은 형식과 부분군 검사를 통과한다고 둠 (공격자에게 가장 유리). 형식이 틀린 것은 디코딩에서 싸게 버림.
- 네트워크 층 숫자는 기본값 출처이고, nwaku가 쓰는 nim-libp2p의 새 연결 제한은 찾지 못함. 연결당 10개는 P4만 본 추정.
- 대기열 지연은 모델에 없음.

## 계획에서 달라진 점
- before: 하드웨어 대안은 곱셈기 수만. after: 덧셈기 수도 (6, 8, 10). 몬테카를로 전에 연산 수를 보니 F가 덧셈기에 막혀서 (덧셈이 곱의 3.7배).
- before: f 격자 0.03 다음 0.1. after: f_max를 내려고 0.02–0.20을 0.01 간격으로 추가 (M5A4, M8A8).
