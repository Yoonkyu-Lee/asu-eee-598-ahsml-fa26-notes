# CP14 — 단건 시험의 고정 비용 줄이기

2026-11-01 시작. 요약은 [CHECKPOINT.md](../CHECKPOINT.md), 그림은 아키텍처 보드(L1 "단건 시험의 고정 비용")와 체크포인트 보드.

## 왜 이 CP인가
CP13에서 검증 유닛의 크기를 정한 것은 **틀린 증명만 오는 폭주**였다. 이때는 모든 증명이 디코딩 + 단건 시험을 치르고, 그 비용(Fp 곱 43,507 / 덧셈 153,035, CP13 기록)이 곱셈기 5개 → 8개, 덧셈기 4개 → 8개를 불렀다.
CP11의 기록기는 두 군데를 일부러 비싸게 셌다 (cyclotomic 제곱을 일반 제곱으로, 지수 x를 이진수로). 그리고 검증키에 고정된 값(공개 입력 기저점 IC)을 미리 계산에 쓰지 않았다.
이번 CP는 단건 시험을 실제 라이브러리 수준(arkworks)과 그 너머로 줄여, 곱셈기 8 + 덧셈기 8을 더 작은 구성으로 되돌릴 수 있는지 본다.
- 형식: **목적형**. [구현] [디자인].
- 답할 질문: 틀린 증명 하나를 버리는 데 드는 곱·덧셈을 얼마나 줄일 수 있나? 그러면 100 Mbps 전부 틀린 폭주를 지키는 가장 작은 (곱셈기, 덧셈기)는?

## 그림 (설계, 결과 전)
```
 틀린 증명 1개를 버리는 길 (지금)                         바꾼 뒤
 ┌ 디코딩 ─ 제곱근 3번 ─ 부분군 검사 ┐                   ┌ 디코딩 ─ 제곱근 3번 (O5: 압축 안 함이면 곡선 위 검사만) ┐
 │                                    │                   │  부분군 검사는 ▶ 시험을 통과한 증명만 (O4)               │
 ├ 공개 입력 MSM (Straus, 254번 두배) ┤        ──▶       ├ 공개 입력 MSM: 미리 계산한 표에서 더하기만 (O3, 표는 DRAM) ┤
 ├ Miller loop                        ┤                   ├ Miller loop (그대로)                                     ┤
 └ 최종 지수승: x 지수승 3번          ┘                   └ 최종 지수승: cyclotomic 제곱 (O1) + x의 NAF (O2)          ┘
```

## 대안 (최적화, 서로 독립이라 하나씩 켜고 끔)
| | 무엇 | 줄이는 곳 | 대가 |
|---|---|---|---|
| O1 | cyclotomic 제곱 (Granger–Scott, arkworks와 같음) | 최종 지수승의 제곱 186번: Fp12 제곱 곱 36 → 18 | 없음 (공식만) |
| O2 | x 지수승을 NAF로 (arkworks와 같음, 역원은 켤레라 공짜) | 최종 지수승의 곱 횟수 | 없음 |
| O3 | 공개 입력 MSM을 고정 기저 표로 (창 w 비트, 표 항목 = d·2^(wi)·ICⱼ) | 두배 254번이 사라지고 더하기만 | 표 (2^w − 1)·⌈254/w⌉·64 B × 기저 6개, 호스트 DRAM. w = 4: 약 368 KB, w = 8: 약 3.1 MB |
| O4 | G2 부분군 검사를 시험 통과 뒤로 미룸 | 틀린 증명은 부분군 검사를 안 함 | 맞는 증명은 비용 그대로. 아래 안전 논증 |
| O5 | 증명을 압축하지 않고 보냄 (곡선 위 검사만) | 제곱근 3번 | 증명 128 B → 256 B (메시지 1 KB 가정 안이면 폭주 속도는 그대로). **전선 형식이 바뀜** |

O4 안전 논증: 시험이 실패한 증명은 어차피 버린다 (부분군 밖의 점이 섞였든 아니든 버리는 것은 안전하다). 받아들이는 증명은 언제나 부분군 검사까지 마친다. 그러니 받아들이는 집합은 지금과 같다. 공격자가 "시험은 통과하고 부분군에서 떨어지는" 증명을 만들면 그 증명은 지금 비용 그대로 치른다 (나빠지지 않음). 그런 증명을 공짜로 만들 수 있는지는 이 CP에서 따지지 않고, 최악의 경우를 둘 다 적는다.

## 판정 규칙 (결과를 보기 전에 적음)
- **D1 (최적화마다)**: (a) 자체 시험에서 원래 공식과 같은 값을 낸다 (cyclotomic 원소에서 제곱 비교, 지수승 비교, MSM 비교, 페어링 쌍선형성), (b) 대가가 한도 안: 칩 SRAM 추가 ≤ 64 KB, 폭주 중 표 읽기 DRAM 대역 ≤ 0.85 GB/s (LPDDR4 8.5 GB/s의 10%). 둘 다 지키면 켠다.
- **D2 (하드웨어)**: 켠 최적화로 CP13과 같은 모델(전략 D + B, f ∈ [0, 1], 나란히 돌리기 이용률)을 다시 돌려, 최저 용량 ≥ 12,207/s인 (곱셈기 M, 덧셈기 A) 중 면적이 가장 작은 것. M ∈ {5, 6, 7, 8}, A ∈ {4, 5, 6, 8}.
- **D3 (전선 형식)**: O5는 칩 안 최적화(O1–O4)만으로 고른 M을 하나 이상 더 줄일 때만 켠다. 아니면 압축을 유지한다.
- O4의 최악 경우: "시험 통과·부분군 실패" 증명만 오는 폭주에서도 D2 구성이 12,207/s를 지키는지 따로 적는다. 못 지키면 이 경우의 비용을 공격자에게 묻는 근거(맞는 증명이 필요한가)를 다음 질문으로 남긴다.

뒤집을 조건:
- S1: O1–O4로도 M = 8이 필요하면 CP13 결정을 유지하고, 다음은 클럭(곱셈기 파이프라인, CP10의 손 파이프라인 조건)으로 간다.
- S2: 덧셈기가 곱셈기보다 많이 필요해지면 (A > M), 덧셈 쪽 하드웨어(3입력 덧셈기, 상수 곱 9를 시프트-덧셈으로)를 다음 후보로 적는다.
- S3: 어떤 최적화든 자체 시험에 실패하면 버린다.

### 판정
- **D1**: O1–O4 모두 켬 (자체 시험 통과, 칩 SRAM 추가 0, 표 읽기 0.125 GB/s ≤ 0.85). O3은 w = 8 (표 3.1 MB, 호스트 DRAM; 읽기가 적음).
- **D2: 곱셈기 6 + 덧셈기 6** (13,429/s, 여유 10%). 검증 유닛 2.69 → **2.12 mm²**, 칩 11.9 → **11.3 mm²**, 폭주 중 칩 최대 1.05 W. 누설 10.9 → 12.4 mW (추정: CP12 단가로 곱셈기 1개, 덧셈기 2개 추가). 칩 유휴(게이팅 전)는 16.24 + 12.42 = 28.7 mW (D3b 50 mW 안).
- **D3: 압축 유지.** O5는 가장 작은 구성을 6×6에서 못 줄임 (5×6이 11,883/s로 97%).
- O4 최악 경우: "시험은 통과하고 부분군에서 떨어지는" 증명은 배치 해결에서 맞는 증명과 똑같이 움직이고 부분군 검사를 치른다 → 비용이 맞는 증명과 같다. 맞는 증명 비율을 모두 포함한 위 최저(f ∈ [0, 1])가 이미 이 경우를 덮는다.
- S1 안 걸림 (M = 6). S2 안 걸림 (A = M). S3 안 걸림.

## 해석
1. **CP13의 8 + 8 중 상당 부분은 우리 기록기가 보수적으로 센 탓이었다.** 라이브러리가 이미 하는 O1 + O2만 넣어도 7 × 8로 내려간다. 사이클 모델의 단순화가 하드웨어 크기를 한 단계 바꿀 수 있다는 것: 단순화는 "보수적"이라도 결과 쪽에 적어 둬야 한다.
2. 라이브러리 너머의 큰 이득은 **검증키가 고정**이라는 성질(O3)에서 왔다. 공개 입력 MSM이 곱 9,111 → 2,115로, 틀린 증명 비용의 16%가 사라졌다. 칩 밖 DRAM 3.1 MB와 0.125 GB/s를 쓰는 맞바꿈이다.
3. 이제 틀린 증명 비용(곱)의 87%가 Miller loop(곱 16,339)와 최종 지수승(8,331)이고, 덧셈이 곱의 4.2배다. 남은 손잡이는 덧셈 쪽이다: 5 × 6이 97%까지 왔으므로, 덧셈 수를 7% 줄이거나 덧셈기를 바꾸면(예: ×9 상수 곱을 시프트-덧셈 한 번으로) 곱셈기 5개도 가능해 보인다. 면적 이득은 0.28 mm² (칩의 2.5%).
4. 공격자의 최선은 틀린 증명만 보내는 것이 아니라 **약 15%만 섞는 것**이 되었다. 맞는 증명이 부분군 검사를 치르면서 배치는 깨지는 지점.

## 한계
- 전부 모델. 단건 처리량은 독립 시험을 나란히 돌리는 마이크로코드를 가정함 (한 번에 하나면 6×6에서 11,303/s로 모자람).
- 기계별 이용률은 CP11 배치에서 잰 값을 그대로 씀. 단건 위주 폭주의 연산 비율(덧셈이 곱의 4.2배)은 CP11 배치(2.5배)와 달라, 덧셈기가 적은 기계에서는 이용률이 다를 수 있다.
- O3 표는 DRAM에서 무작위 64 B 읽기. 스칼라(공개 입력)를 미리 알기 때문에 미리 읽기가 가능하다고 둠 (지연은 모델에 없음). 표는 검증키가 바뀔 때마다 다시 만든다 (오프라인).
- 덧셈기·곱셈기 추가의 포트·크로스바 비용은 없음 (CP13과 같음).
- 부분군 검사는 ψ(B) = [6x²]B (arkworks) 그대로. 더 빠른 검사(63비트 스칼라)는 따지지 않음: 미룬 뒤에는 맞는 증명에만 붙기 때문.
